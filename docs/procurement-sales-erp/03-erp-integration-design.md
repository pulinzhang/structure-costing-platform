# ERP 双向接口 — 设计说明

> **状态：设计定稿，未落地。** 平台仍负责核算。与 ERP 的交换分写入、读取两个方向，使用同一种传输方式。平台不替代 ERP，不在 ERP 内重建订单、库存和发票流程。

---

## 0. 一句话

**ERP 双向接口包含写入和读取。** 写入把审核通过的采购结算结果、销售核价结果写入甲方 ERP。读取按书面字段对照从 ERP 取得约定的业务数据。写入失败不回滚平台上的核价，也不改已经算出的金额。读取不改写 ERP 中的源数据，也不覆盖已审核的核价金额。

---

## 1. 两个方向

| 方向 | 谁可以发起 | 交换什么 |
|------|------------|----------|
| 写入·销售结果 | 销售部、管理员 | 已审核供货总成的销售价，并带基数和四项比例费用 |
| 写入·采购结果 | 采购部、管理员 | 已审核采购对象的应成本 |
| 读取 | 字段对照指定的角色 | 对照表列明的 ERP 业务数据。未列明的对象不读 |

销售部不能写入采购结果，采购部不能写入销售结果。读取不因此打开另一部门的核价结果。

写入不包含：

- 未审核、核算失败的行
- 冲压工序、钢卷、模具明细
- 材料清单全文、工艺确认表
- 系统费率的当前设置（只写这张卡当时用的费率快照）
- 在 ERP 内维护订单、出库、发票、库存流程

平台上已审核的应成本、基数和销售价只由核价计算和审核改变。对方单据号只作为写入回执留在接口记录上，不参与下次计算。

---

## 2. 写入·销售结果字段

一行对应一个已审核通过的供货总成、一个账期。

| 字段 | 来源 |
|------|------|
| 基地、项目 | 核价范围 |
| 年、月 | 账期 |
| 零件号、零件名称 | 供货总成 |
| 基数 | 月总账 |
| 财务费率、财务费 | 卡上快照和金额 |
| 管理费率、管理费 | 同上 |
| 报废费率、报废费用 | 同上 |
| 税前利润率、税前利润 | 同上 |
| 比例费用合计 | 四项之和 |
| 单件运输费、仓储捆包费 | 非比例，一并带上，避免对方只用比例重算销售价 |
| 销售价 | 总费用 |
| 平台结果行号 | 平台主键，供对账 |
| 审核通过时间 | 写入时抄录 |

对方用这些字段入账或形成销售侧价格。不得只写销售价而丢掉基数和费率，否则对不上账时无法解释。

---

## 3. 写入·采购结果字段

一行对应一个已审核通过的采购对象、一个账期。

| 字段 | 来源 |
|------|------|
| 基地、项目 | 核价范围 |
| 年、月 | 账期 |
| 零件号、零件名称 | 采购对象 |
| 分类 | 冲压件、分总成或退化供货件 |
| 供应商 | 清单上指定的名称；未指定则空，不替对方猜 |
| 应成本 | 采购结算价 |
| 平台结果行号 | 平台主键 |
| 审核通过时间 | 写入时抄录 |

不写管理费、销售价、比例费率。采购核价表的工序明细不进这一方向。

---

## 4. 读取

读取对象和字段在接口开工前以书面字段对照封闭。对照表至少写明：ERP 对象、平台落点、业务键、发起角色、该字段是仅供对照还是可作为尚未审核期间的核算输入。

| 规则 | 约定 |
|------|------|
| 范围 | 对照表没有的对象不读 |
| 落点 | 进入平台接口记录。不直接改核价卡 |
| 重复读取 | 按业务键更新同一条读取记录，不新造核价结果 |
| 已审核金额 | 不覆盖应成本、基数、销售价，不自动触发重算 |
| 标为输入的字段 | 只作用于尚未审核的期间 |
| ERP 源数据 | 平台不改写 |
| 失败 | 记入读取记录。已有核价结果保持不变，允许按原对照重读 |

---

## 5. 何时可以写入

同时满足才允许：

1. 该行核算状态正常
2. 该行所在账期批次已审核通过
3. 操作人属于对应部门，或是管理员
4. 甲方 ERP 的地址、账号和写入、读取字段对照已经书面确认

缺任一条，整批不写，并说明缺哪一条。不把失败行悄悄跳过还报成功。

同一行再次写入使用同一业务键：基地 + 项目 + 年 + 月 + 零件号 + 结果种类（销售或采购）。

| 对方状态 | 平台行为 |
|----------|----------|
| 没有这张单，或对方允许覆盖 | 写入或更新，记下对方单据号 |
| 对方已引用、不允许覆盖 | 拒绝这一行，保留平台原金额，提示“对方已引用” |
| 超时或对方报错 | 这一行记失败，可原样重写。不改平台金额 |

重写不新造一条平台结果，不触发重算。

---

## 6. 传输方式

开工前双方书面选定一种，写入和读取都走这一种，不并行做两套。

| 方式 | 适用 |
|------|------|
| 甲方 ERP 提供的 Web 接口 | 对方能给出地址、认证方式、写入回执和读取查询 |
| 约定格式的文件交换 | 对方以文件交接。写入字段仍是第 2、3 节，读取字段仍是第 4 节的对照表，并约定目录和文件名 |

未选定之前不开发接口程序。选定之后，写入字段只允许在第 2、3 节里删减；读取字段以对照表为准。增加对象或字段要走合同变更。

认证信息由甲方提供，放在甲方环境，不写进源码和文档样例。平台保存接口配置，以及每次写入、读取的记录：成功、失败、对方单据号或业务键、失败原因、时间、操作人。

---

## 7. 和核算的关系

写入是把已审核结果交到 ERP，不是另一次核价。读取是把 ERP 数据取回平台，也不代替月度计算。

- 写入程序只读已落库的核价卡和采购对象身份
- 不调用月度引擎，不改应成本、基数、费率、销售价
- 写入失败不影响已经审核的结果
- 反审核之后，已写入的行标记为待重写，不自动冲销 ERP 单据。冲销或作废由 ERP 按回执处理，平台再次写入前必须重新审核通过
- 读取失败不覆盖已经审核的结果

---

## 8. 验收时要看到的事

用甲方提供的测试环境或测试文件目录，不要只用口头说明。

1. 未审核的销售行和采购行写不进 ERP。
2. 审核通过后，销售部能写入，回执或文件里的销售价等于页面上的销售价，基数乘四项费率等于比例费用。
3. 采购部能写入应成本，报文里没有销售价和管理费。
4. 销售部账号写入采购结果被拒绝，采购部账号写入销售结果被拒绝。
5. 对方返回失败时，平台金额不变，同一行可以再写一次。
6. 对方已引用时，平台拒绝覆盖并给出原因。
7. 按字段对照至少读回一条数据。平台有读取记录，ERP 源数据未被改写，已审核核价金额不变。
