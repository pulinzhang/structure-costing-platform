## 1. 什么是框架（Framework）？

### 生活类比

想象你要盖一栋房子：

| 方式       | 描述                                               | 时间           |
| ---------- | -------------------------------------------------- | -------------- |
| 不使用框架 | 从零开始：挖地基、烧砖、炼钢筋、做门窗...          | 几个月甚至几年 |
| 使用框架   | 用预制件盖房：地板、墙壁、屋顶都准备好了，只需组装 | 几天           |

### 编程中的框架

框架就是别人帮你写好了 **Web 开发中常用的基础设施代码**，你只需要专注于写自己的业务逻辑。

### 代码对比

**没有框架（自己处理 HTTP）**

```python
socket.listen(8000)
while True:
    request = socket.accept()
    method = 解析请求方法      # 可能有 50 行代码
    path = 解析请求路径        # 可能有 50 行代码
    headers = 解析请求头       # 可能有 50 行代码
    body = 解析请求体          # 可能有 50 行代码
    ...                       # 以上代码可能有几百行！
```

**有框架（FastAPI）**

```python
@app.get("/")
def index():
    return "Hello!"
# 3 行搞定！
```

## 2. 什么是 FastAPI？

FastAPI 是一个 **现代的 Python Web 框架**，用于构建 API。

### 特点

| 特点                 | 说明              |
| -------------------- | ----------------- |
| ✅ 速度快            | 性能接近 Node.js  |
| ✅ 自动生成 API 文档 | 访问 `/docs` 查看 |
| ✅ 类型检查          | 减少 bug          |
| ✅ 异步支持          | 高并发            |
| ✅ 容易学习          | 语法简洁          |

### 同类框架对比

| 框架    | 类型     | 特点                          |
| ------- | -------- | ----------------------------- |
| Django  | 全栈框架 | 什么都自带（ORM、模板、后台） |
| Flask   | 微框架   | 简单灵活                      |
| FastAPI | API 框架 | 自动文档、类型安全、异步      |

### FastAPI 能做什么？

1. 构建 REST API（前后端分离）
2. 构建前后端不分离的 Web 应用（配合 Jinja2 模板）
3. 构建微服务
4. 构建实时通信（WebSocket）

## 3. main.py 文件结构

`main.py` 是整个应用的 **入口文件**。

### 比喻

就像一栋大楼的 **前台接待处**：

| 前台职责       | 对应代码               |
| -------------- | ---------------------- |
| 迎接访客       | 接收 HTTP 请求         |
| 分配到不同部门 | 路由到不同功能         |
| 处理公共事务   | 中间件（日志、权限等） |

### 文件结构

```
main.py
├── 1. 导入依赖
├── 2. 定义 lifespan 函数（启动/关闭时的操作）
├── 3. 定义 create_app 函数（创建应用、注册路由）
├── 4. 创建 app 实例
└── 5. 运行应用（if __name__ == "__main__"）
```

## 4. 什么是装饰器？

### 定义

装饰器是一种特殊的函数，它可以在 **不修改原函数代码** 的情况下，给函数添加额外的功能。

### 语法

```python
@装饰器名
def 函数名():
    pass
```

相当于：

```python
函数名 = 装饰器名(函数名)
```

### 举例说明

```python
# 定义一个装饰器
def my_decorator(func):
    def wrapper():
        print("调用函数之前")
        func()           # 调用原函数
        print("调用函数之后")
    return wrapper

# 使用装饰器
@my_decorator
def say_hello():
    print("你好！")

# 调用时，效果相当于：
# say_hello = my_decorator(say_hello)
# say_hello()
# 输出：
#   调用函数之前
#   你好！
#   调用函数之后
```

### 常见装饰器

| 装饰器                 | 作用               |
| ---------------------- | ------------------ |
| `@app.get()`           | 注册 GET 请求路由  |
| `@app.post()`          | 注册 POST 请求路由 |
| `@asynccontextmanager` | 创建上下文管理器   |
| `@property`            | 把方法变成属性     |

## 5. 什么是 async/await？

### 关键字含义

| 关键字      | 含义                 |
| ----------- | -------------------- |
| `async def` | 定义一个"异步函数"   |
| `await`     | 等待一个异步操作完成 |

### 简单理解

| 类型     | 行为             | 比喻                                                 |
| -------- | ---------------- | ---------------------------------------------------- |
| 普通函数 | 一件一件顺序做   | 同步：等外卖送到 → 吃饭 → 等咖啡送到 → 喝咖啡        |
| 异步函数 | 可以同时做多件事 | 异步：下单外卖和咖啡 → 两者同时进行 → 都到了一起吃喝 |

### 代码示例

```python
# 普通函数
def sync_func():
    result1 = do_task1()      # 等待完成
    result2 = do_task2()      # 等待完成
    return result1 + result2

# 异步函数
async def async_func():
    task1 = do_task1()        # 发起任务，不等待
    task2 = do_task2()        # 发起任务，不等待
    result1 = await task1     # 等待结果
    result2 = await task2     # 等待结果
    return result1 + result2
```

## 6. @app.get() 和 app.get() 的区别

### 目的相同

都是 **注册路由**，告诉 FastAPI：当用户访问某个 URL 时，调用哪个函数处理。

### 两种写法

| 写法       | 形式                 | 复杂度     |
| ---------- | -------------------- | ---------- |
| 装饰器写法 | `@app.get("/")`      | 简洁，推荐 |
| 手动写法   | `app.get("/")(函数)` | 啰嗦       |

### 代码对比

```python
# ========== 装饰器写法（简洁，推荐）==========

@app.get("/")
async def root():
    return "Hello"

# ========== 手动写法（啰嗦）==========

def root():
    return "Hello"
app.get("/")(root)
```

### 原理

```python
# @app.get("/") 本质上做了两件事：
# 1. app.get("/") 调用，返回一个装饰器函数
# 2. @ 语法把这个装饰器应用到下面的函数上

# 所以：
# @app.get("/")
# def root():
#     pass

# 等价于：
# def root():
#     pass
# root = app.get("/")(root)
```

### 框架约定

这是 **FastAPI 框架的约定写法**，就像 Python 用缩进一样，大家都知道这么写。

## 7. 什么是中间件？

### 定义

中间件是在 **请求处理过程中插入的"拦截器"**。

### 用途

| 用途      | 说明               |
| --------- | ------------------ |
| 记录日志  | 记录每个请求的信息 |
| 验证权限  | 检查用户是否登录   |
| 处理 CORS | 处理跨域请求       |
| 性能监控  | 统计响应时间       |

### 执行顺序

```
请求 → 中间件1 → 中间件2 → 路由 → 中间件2 → 中间件1 → 响应
```

### 代码示例

```python
@app.middleware("http")
async def log_middleware(request: Request, call_next):
    # 1. 请求处理之前
    start_time = time.time()
    print(f"收到请求: {request.url}")

    # 2. 继续处理请求
    response = await call_next(request)

    # 3. 响应处理之后
    duration = time.time() - start_time
    print(f"请求完成，耗时: {duration}秒")

    return response
```

## 8. 应用生命周期管理

### 什么是上下文管理器？

上下文管理器可以自动处理 **"开始"和"结束"** 操作。

### 常见例子：打开文件

```python
with open("test.txt", "r") as f:
    content = f.read()
# with 代码块结束后，文件自动关闭

# 这里 "with" 就是一个上下文管理器
# - 开始时：打开文件
# - 结束时：关闭文件
```

### FastAPI 的生命周期

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # ========== yield 之前：启动时执行一次 ==========
    print("应用启动")
    initialize_resources()
    ...
    yield  # <-- 分界线
    # ========== yield 之后：关闭时执行一次 ==========
    print("应用关闭")
    cleanup_resources()
```

### 生命周期中的常见操作

| 阶段   | 常见操作                                   |
| ------ | ------------------------------------------ |
| 启动时 | 初始化日志、创建目录、连接数据库、加载配置 |
| 关闭时 | 关闭数据库连接、保存状态、清理临时文件     |

## 常见问题

### Q: 为什么需要中间件？

A: 中间件可以统一处理一些公共逻辑，避免在每个路由函数中重复写。比如日志记录，每个路由都要写，但用中间件只需要写一次。

### Q: async/await 和普通函数有什么区别？

A: 异步函数可以 **同时处理多个请求**，而普通函数一次只能处理一个。在高并发场景下，异步函数性能更好。

### Q: 什么时候用 @app.get()？什么时候用 app.get()？

A: 99% 的情况下用 `@app.get()`。只有在你需要动态决定路由时才会用 `app.get()`。

### Q: lifespan 函数为什么用 yield？

A: `yield` 是分界线：

- `yield` 之前 = 启动时执行
- `yield` 之后 = 关闭时执行

这是 `@asynccontextmanager` 装饰器的语法规定。
