# 产品质量先期策划（APQP，Advanced Product Quality Planning）：先模具布点、后工艺确认

> **状态：已落地。**  
> 对照现网：[模具布点](stamping-die-management-design.md)、[工艺确认表](stamping-process-confirmation-design.md)。  
> 侧栏已按本顺序摆：冲压模具在冲压工艺之上（`static/index.html`）。  
> 硬约束：分层与切片见 [architecture.md](../architecture.md)。

---

## 0. 一句话

按汽车行业 **产品质量先期策划**（**APQP**，**A**dvanced **P**roduct **Q**uality **P**lanning；亦称先期产品质量策划），模具布点 **不依赖** 已签字工艺；工艺确认表 **只选采购基地**，项目从文件识别。  
下游冲压厂可以只有工艺确认表、没有布点：工艺上传 **不要求** 已入库布点。主机厂若要算模具费，再另传布点。  
布点上传 **必须先选采购基地**；文件标题项目须与手工填写的项目一致。布点入库后每道需要模具的工序都必须有编号：Excel 有则用原文；**空则按 §4.4 自动生成**。工艺确认表里模具编号 **可有可无，不得挡导入**。  
布点阶段还没有定点供应商，**布点不读、不认、不回填供应商名称**。

APQP 出自 AIAG《Advanced Product Quality Planning and Control Plan》（产品质量先期策划和控制计划），是 IATF 16949 五大核心工具之一（其余为 PPAP、FMEA、MSA、SPC）。产品实现顺序是：设计和开发 → **工装与模具策划** → 过程设计和开发（工艺确认、控制计划）→ 试生产与 PPAP。本平台只取「先工装/模具、后过程确认」这一条时间顺序，**不**在此实现 APQP 五阶段交付物清单。

下文「APQP」均指上述汽车行业全称，不再展开。

## 1. 业务事实（为什么改）

| 阶段 | 先期策划含义 | 平台事实 |
|------|-----------|----------|
| 模具布点 | 项目刚开模，有零件、工序构想、模具外形与 **模具编号** | 此时 **还不知道** 哪家冲压厂中标 |
| 工艺确认表 | 定点之后，双方签字的工艺与吨位 | 此时才有 `stamping_supplier`；模具编号可能仍空、可能后补 |

现网把依赖写反了：布点上传必须该基地+项目已有工艺；子表 `die_number` 从工艺按零件号+工序号回填；有尺寸却没有工艺侧唯一编号则整单失败；供应商/版本也从工艺回填。这等于 **没有签字工艺就不能建模具台账**，也把「还没定点」的布点绑死在供应商上。

本设计把顺序扳回来，**不改**两套表各自的核价角色：

| | 模具布点 | 冲压工艺确认表 |
|--|----------|----------------|
| 核价角色 | 模具费依据（重量 / 尺寸 / `alloc_ratio`） | 加工费 + 材料（含利废 / 家模） |
| 模具编号 | Excel 有则保留；缺则按 `DP-40-{项目}-流水` 自动补（见 §4） | **可选**，空不拒单 |
| 供应商 | **不出现** | 覆盖键之一（基地+厂+车型+版本） |

禁止用布点改工艺利废；禁止用工艺吨位冒充模具费。这一点与现网两份设计一致，只改 **导入顺序与编号/供应商归属**。

## 2. 目标顺序（导入）

```text
采购基地（系统配置，布点上传必选）
    → 上传模具布点（项目：手填或已有布点；文件标题项目须与所选一致）
    →（可并行）维护模具单价（基地+项目，仍无供应商）
    → 上传冲压工艺确认表（只选基地；车型/厂/版本从文件识别；模具编号可空；**不要求**已有布点）
    → 冲次单价 / 加工费 / 年度模具费 / 零件核价 …
```

侧栏保持：**冲压模具 → 冲压工艺 → 冲次单价 → 冲压加工费 → 冲压模具费**。  
上传页文案与校验必须跟侧栏一致：布点 **禁止**再提示「请先上传冲压工艺确认表」。工艺页 **不要**强制选布点项目、**不要**提示「请先上传模具布点」才能传工艺。

**允许：** 没有布点就传工艺（冲压厂侧常见）。有布点时两套表仍按各自核价角色使用，互不挡导入。  
**覆盖布点时：** **不得** 再要求工艺里已有编号，也 **不得** 用工艺供应商去匹配布点行。

### 2.1 减少操作人员认知错误

行业顺序（先开模、后签工艺）不反；平台要同时服务主机厂布点与 **没有布点表的下游冲压厂**。工艺页不要做成「必须先有布点」。界面只用中文，**不要**写英文字段名。

| 容易混的点 | 操作员会怎么想 | 页面必须怎么做 |
|------------|----------------|----------------|
| 布点能填项目，工艺没有项目框 | 「工艺页漏了项目」 | 写明：项目写在工艺文件名/表头里，本页只选基地 |
| 工艺没有布点也能传 | 「是不是坏了」 | 写明：没有布点也可以传工艺；算模具费再传布点 |
| 布点页没有冲压厂 | 「漏了供应商」 | 写明：布点按项目，冲压厂在工艺确认表里才有（尚未定点） |
| 空号被系统补上 | 「表里没号，列表里哪来的」 | 成功文案写「空号已按规则生成 N 条」；列表/导出能看到入库编号 |

**布点上传页（控件下 + 右栏「说明」，推荐原文）：**

> 请先选择采购基地，再手工填写项目。  
> 文件名或标题里的项目必须和填写的一致，不一致将退回、不会入库。  
> 本页不选冲压厂：开模时尚无定点供应商。  
> 模具编号可空，系统按规则自动编号；已填写的编号保持不变。

控件旁短句：基地「必选」；项目「手工录入。须与文件名或标题里的项目一致。」；文件「项目须与上方填写一致」。

**工艺上传页（控件下 + 右栏，在利废说明之前或并列，推荐原文）：**

> 本页只选采购基地。项目、冲压厂、版本从文件名或表头识别。  
> 没有模具布点也可以上传。模具编号本表可空。  
> 若要算模具费，再另传模具布点。

**失败文案（Toast / 任务 message，禁止只写「校验失败」）：**

| 情况 | 文案须同时出现 |
|------|----------------|
| 布点文件项目与填写的不一致 | 「文件项目为 {识别}，与填写的项目 {表单} 不一致」 |
| 未选基地 / 布点未填项目 | 「请选择采购基地」/ 布点：「请填写项目」 |

## 3. 布点：不认供应商

### 3.1 写死

| 禁止 | 说明 |
|------|------|
| 从布点 Excel 解析供应商 / 冲压厂 | 样本本就没有该列；即使以后有人加一列，Parser **不映射** |
| 上传前要求工艺库存在 | 删掉 `exists_location_vehicle_model` 门槛 |
| 按零件号到工艺库取唯一「供应商+版本」 | 删掉 `process_identity` 整单拒绝 |
| 写入时回填 `stamping_supplier` / `version` | 布点主表这两列保持可空，**本期写空**；覆盖上传也不从工艺补 |
| 用供应商当覆盖键 | 覆盖键仍是 **基地 + 项目** 整包替换 |

列表 / 导出 **不要再筛供应商、版本**（筛选项来自回填值，回填取消后这两维没有业务含义）。导出也不再带这两列作为身份。旧库里已回填的值：覆盖重传后变空；不覆盖则残留，界面不当作筛选条件。

模具费计算锁与范围本来就是 **年 + 基地 + 项目**；供应商只是附加筛。落地时附加筛可保留「空=全部」，但布点新数据供应商为空，筛「某厂」会筛不到新布点——符合「模具费按项目摊、尚未定点」的事实。不要为了筛选项再去工艺表反填。

### 3.2 上传表单

| 步骤 | 控件 | 规则 |
|------|------|------|
| 1 | 采购基地 | **必选，不可空。** 未选不得提交。选项与工艺上传一致：系统配置的四基地（大连 / 芜湖 / 鄂尔多斯 / 青岛），**不要**再从 `stamping_parts` 去重。无工艺数据时必须仍能选。 |
| 2 | 项目 | **必选，手工填写。** 不要下拉选择。须与文件名/标题识别出的项目一致。 |
| 3 | 文件 | `.xlsx` / `.xls`，异步 `start_upload`。 |

后端（Service，失败 `BusinessException`，不落库）：

1. 基地、项目均非空。缺基地 → 「请选择采购基地」。缺项目 → 「请填写项目」。
2. Parser 从文件名/标题得到的 `vehicle_model` 与表单项目一致（均经 `normalize_vehicle_model`）。不一致 → 「文件项目为 {识别}，与填写的项目 {表单} 不一致」，直接退回。
3. 识别不出项目 → 现网同类文案（文件名须含「项目冲压模具布点工艺清单」）。

下载模板仍要；模板含 **模具编号** 列，单元格可空（见 §4）。

### 3.3 模具单价

现网「新增须工艺库已有该基地+项目」与「先布点」冲突。改为：

- 新增 / 修改：基地来自系统配置；项目可手填或选自已有布点。
- **不再**要求 `stamping_parts` 先有数据。
- 唯一键仍是基地 + 项目，仍无供应商。

## 4. 布点：模具编号（Excel 或自动补）

### 4.1 来源优先级

编号只来自布点 Excel 或本切片 Service 补号，不对照工艺工序。

| 顺序 | 来源 | 说明 |
|------|------|------|
| 1 | 布点 Excel「模具编号」去空白后非空 | **原样入库**，不改写、不校验是否符合 §4.4 格式（厂里已编的号可能不是 `DP-40-…`） |
| 2 | 需要模具的工序（长/宽/高至少一项有值）且单元格空 | **Service 按 §4.4 生成**，写入子表；**不回写**用户上传的原文件 |
| 3 | 仅「共用 / 合并」等共模标记、无外形 | **保持空**，不发流水（不是一副新模） |

Parser 只读格：有列则映射，无列则各行 `die_number = None`。**表头可以没有「模具编号」**（旧 A～AC 样本可直接传），视为全部走步骤 2/3。下载模板仍在「套数」与「预估模具尺寸」之间放该列，方便已有号的人填。

子表注释改为「来自布点 Excel 或上传时按规则生成」，不再写「来自冲压工序」。生成发生在 **Service**，不在 Parser。

### 4.2 行级规则（不再因缺号拒单）

| 行 | 模具编号 |
|----|----------|
| 长、宽、高 **至少一项有值**，Excel 已填 | 用 Excel |
| 同上，Excel 空（或无该列） | **自动补** §4.4，不失败 |
| 仅「共用 / 合并」等共模标记、无外形 | 允许空 |
| 同一零件内工序号重复 | 仍整单失败（现网已有） |
| 左右共模要共用一号 | **Excel 填同一个号**；两边都空则会各拿一个流水（两副模），系统不猜 |

重量与 7.85 外形核对（相对差 > 10% 整单拒绝）**保留**，与编号无关。

### 4.3 校验与补号时机

外形核对、工序号重复等在 **覆盖删除之前** 做完；失败不改已有布点。  
自动补号用到的「已占用流水」含：**本文件已填的号** + **覆盖删除前** 该基地+项目库中已有的号（见 §4.4）。补号完成后再删旧布点、写入新行。不再列出「工艺确认表文件名 / 冲压厂 / 版本」。

### 4.4 自动编号规则

仅当步骤 2 触发。格式（段之间为 ASCII 连字符 `-`，**无空格**）：

```text
DP-40-T13J-001
│  │  │    └── 三位流水号（001～999）
│  │  └─────── 项目代号 = 本次上传的 vehicle_model（例：T13J）
│  └────────── 模具类别/等级代号，**固定 40**
└───────────── 固定前缀 DP（Die Project / 公司模具标识）
```

图中的 `T13J` 是示例，**禁止**写死项目。落地用 `normalize_vehicle_model` 后的项目字符串，如 `DP-40-T2AA-003`。

| 字段 | 写死 |
|------|------|
| `DP` | 常量，不从 Excel 读，不随基地变化 |
| `40` | 常量（模具类别/等级代号），本期不按钢板模/级进模分码 |
| 项目 | 表单所选 / 文件标题解析且已与表单对齐的项目 |
| 流水 | 十进制三位，不足补零：`001` … `999` |

**流水怎么取：**

1. 扫描范围 = 本文件已填编号 ∪ 该 `location` + `vehicle_model` 下覆盖前库中全部 `die_number`。
2. 只认完全匹配 `^DP-40-{项目}-(\d{3})$` 的号，取出其中的三位数字；其它格式（厂编、旧工艺回填）**不占**本规则流水。
3. 下一个号 = 已占用流水的 **最大值 + 1**（不回填空洞：已有 `001` 与 `003` 则下一个是 `004`）。库与文件都没有匹配号时从 `001` 起。
4. 本文件多行需要补号：按 Excel 行号升序（同行内按工序顺序）依次 +1，保证同一次上传稳定。
5. 下一个将超过 `999` → **整单失败**，不删旧布点。提示该项目本规则编号已满，须在 Excel 自行编号或清理占用号。

补进库的是完整字符串（如 `DP-40-T13J-427`），与现网工艺样本中的写法一致。列表 / 导出看到的是入库值；任务成功文案可写「自动编号 N 条」，不必逐条弹。

## 5. 工艺确认表：只选基地，编号可空

工艺上传只选 **基地**，车型从 Excel 头信息自行识别，**不依赖布点**。下游冲压厂没有布点表时仍须能导入工艺。

### 5.1 表单

| 步骤 | 控件 | 规则 |
|------|------|------|
| 1 | 采购基地 | **必选。** 与布点相同：系统配置四基地。未选不得提交。 |
| 2 | 文件 | `.xlsx` / `.xls`。项目、冲压厂、版本仍从文件头识别（覆盖键仍是基地+厂+车型+版本）。 |

Form 只带 `location` + `file`。不要加 `vehicle_model` 表单字段，也不要 `GET /api/stamping/upload/filters`。

### 5.2 后端

Service 在写库之前走现网 `validate_stamping_process_upload_scope`（厂/车型/版本从文件取）。**不要**查布点库是否存在，**不要**对照表单项目号。

### 5.3 模具编号可有可无

| 规则 | 说明 |
|------|------|
| 表头可以没有「模具编号」 | `col_map` 无该键时，各工序 `die_number = None`，**解析成功** |
| 表头有、单元格空 | 仍为 `None`，**不拒单** |
| 表头有、单元格有值 | 原样入库，仅供展示 / 导出工艺卡 |
| 不得用布点编号卡工艺导入 | 缺号、与布点编号字符串不一致，都 **不是** 工艺失败原因 |
| 不得用工艺编号回写布点 | 工艺覆盖写入只动 `stamping_parts` / `stamping_processes` |

加工费仍只读工艺吨位与 `cost_ratio`。模具费仍只读布点重量 / 尺寸 / `alloc_ratio` / **布点上的** `die_number`。

工艺上传页说明须写明：见 **§2.1**（只选基地、不必先有布点、编号可空）。利废说明仍按 [stamping-process-confirmation-design.md](stamping-process-confirmation-design.md)，两段都要在，不要互相覆盖。

模板：工艺模板仍可带「模具编号」列方便有号的厂填写，但说明改为可选。

## 6. 两套编号并存时怎么读

落地后可能出现：布点有号、工艺空；或两边都有但字符串不同。

| 消费者 | 读哪份 |
|--------|--------|
| 年度模具费、缺号提示 | **只读布点** `stamping_die_processes.die_number` |
| 冲压零件列表 / 工艺导出 | 只读工艺子表（可空） |
| 核价引擎加工费 | 不读模具编号 |

缺号提示（现网模具费：有外形无号只提示不拦截）改为看 **布点本行**：有外形行在布点上传时已补号，计算期缺号应只剩共模无外形行（继续不提示）。提示文案 **不要**再写「供应商 …」（布点无厂）。

不在本期做「工艺有号则覆盖布点」或自动对账报表。若以后要对账，另开设计，且对账失败不得挡工艺导入。

## 9. 验收口径（实施后）

- 该基地该项目 **零条** 工艺记录时，布点上传可以成功（文件合法；缺号则自动补）。
- 布点未选基地、或未选/未填项目 → 不得提交；后端缺项 400。
- 布点文件项目与填写的项目不一致 → 退回，不落库。
- 布点文件无「模具编号」表头 → **仍成功**；有外形的空号按 `DP-40-{项目}-流水` 入库。
- 有长或宽或高、编号空 → **补号成功**，不因缺号拒单；流水用尽（将超过 999）才整单失败，不删旧布点。
- Excel 已填 `DP-40-T13J-427` 时，同项目下一空行补 `428`（或该范围已占用的最大流水 +1）。
- 布点 Excel 即使出现供应商字样，入库 `stamping_supplier` 仍为空。
- 工艺未选基地 → 不得提交；后端缺项 400。
- 该基地布点库为空时，工艺上传仍可成功（文件合法）。
- 工艺文件无「模具编号」列，或列全空 → 仍可导入成功。
- 工艺有编号但与布点编号字符串不一致 → 工艺仍成功。
- 布点上传页禁止再要求「先工艺后布点」。
- 布点文件项目与所选不一致的失败文案同时出现识别值与所选值。
