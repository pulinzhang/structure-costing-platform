# 采购核价表 — 设计说明

> **状态：已落地。** 查询页「成本还原 → 采购对象」，导出跟当前筛选条件。  
> 样张：[`采购核价表.xlsx`](采购核价表.xlsx)。只用来认业务：对象、材料、冲次、焊接、结算价。**查询页和导出不照这张表的版式**（不合并单元格，不照双行表头，不照一件七行）。  
> 切片：**`costing` 下单独一块**，不写进总成核价，也不写进采购价格协议，也不写进计算过程。  
> 侧栏单独一组，不挂在「核价」下面。组名 **成本还原**，下面只有一页 **采购对象**。  
> **一块就是一个采购对象**（`section=object`）。块内把构成它的冲压材料、冲压费用、焊接费按原始记录列出来，再合并成这一对象的价。  
> 账期月与爬到所属 L0 与[采购价格协议](procurement-contract-report-design.md)采购对象视图相同。**项目可空**：有值只出该项目，空则该基地该月全部项目。清单规则见 [bom-procurement-objects-design.md](../bom/bom-procurement-objects-design.md)。金额来源与[总成月核价](assembly-costing-design.md)相同；展开方式对齐[计算过程](assembly-cost-restore-design.md)里「只读已落库明细、不重走树」。  
> 计算过程是单张卡的异常页。本表是一个月里每个采购对象的还原宽表，名称仍叫采购核价表。

---

## 0. 一句话

**按一个基地、一个年月，给命中的采购对象各出一块可追溯的成本还原。** 项目可以选，也可以不选。选了只出该项目；不选则该基地该月的项目都在一张表上，块上仍写各自的项目。身份行是采购对象。块内把冲压叶子从原材料净成本收到零件标准成本，再收到这张卡的结算价。退化供货件合并的是名下各叶子；分总成同时列出本对象的焊接费。

---

## 1. 样张里实际有什么

`Sheet1` 是宽表，不是透视汇总。表头两行（第 2–3 行），第 1 行只有「月」。数据从第 4 行起，样张里一件占 7 行（20 件，到第 143 行）。身份列合并；工序按行往下排。

| 事实 | 样张 |
|------|------|
| 基地列 | 没有。基地是这张表的范围，写在表头 |
| 供应商 | 20 件都是「芜湖容大机械制造有限公司」 |
| 项目 | J52 十件，S11 十件，叠在同一张表上 |
| 分类 | 全部「冲压单件」 |
| 冲压模式 | 全部「单干」 |
| 月 | `C1 = 1`。钢材价、废料价用这个月去外部工作簿取列 |
| 工序槽 | 样张固定 7 行。示例件用了 5 道：`BL` / `FO` / `FO` / `PI` / `TR` |
| 外部簿 | `[1]材料+废料`、`[1]冲焊标准`、`[1]焊接标准件`、`[1]结算数据`。本仓库不带这些簿 |

样张 20 行都是冲压单件。系统三种采购对象都出：冲压件、分总成、退化供货件。核对区不进这张表。页面和导出是普通查询表：一行一条明细，对象身份每行都写。不合并单元格，不把一件折成固定 7 行。

身份列对到对象行：

| 样张 | 采购对象 |
|------|----------|
| 主要供应商 | `supplier_name`。未指定则空 |
| 项目 | `vehicle_model` |
| 分类/总成号 | 冲压件 / 分总成 / 退化供货件。样张「冲压单件」即冲压件 |
| 物料编码 | `internal_number` |
| 零件号 / 零件名称 | 本对象的 `part_number` / `part_name`。块内明细行另写叶子零件号，不盖掉对象号 |
| 单车用量 | 从所属 L0 到本对象，`qty` 沿树连乘。对象行上的 `qty` 是相对父件 |

样张原材料公式与零件价 `material_net_per_part` 同一条（损耗 0.003、回收 0.97）。块内材料明细抄这个已落库的数，不重算。

零件单价抄对象卡 `total_amount`（采购视图总成本，等于 `should_cost`）。样张把包装和工装分摊加进单价；现网这两笔在间接费用里。本表单价不含间接费用。

## 2. 统计范围

一张表一个范围。必填：`location`、`year`、`month`。`vehicle_model` 可空。

| `vehicle_model` | 表里有哪些项目 |
|-----------------|----------------|
| 有值 | 只该项目 |
| 空 | 该基地该月全部项目。样张把 J52 和 S11 叠在一张表上，就是这一档 |

```text
采购对象 section=object
  有项目 → 该基地 + 该项目
  无项目 → 该基地
  → 每行爬到所属 L0
  → 该 L0 在这个年月命中，才进表
```

版本不进范围。可选 `supplier_name`，空则含未指定供应商。

选了项目、该项目还没有采购对象清单：拒绝，文案「请先生成采购对象清单」。不选项目、该基地一个清单都没有：同样拒绝。不选项目时，某个项目没有清单不影响其它项目。该月没有命中行：空表。检测未通过仍允许查，表头标明未通过。表头写基地、年、月；选了项目再写项目，不选则写「全部项目」。

对象在清单里就留块。没有对象卡：身份仍在，金额空。卡是 `partial` / `failed`：明细照列，合并行仍抄卡上的数，并标状态和 `calc_message`。断链正是要看见的，不因为状态不满就把明细清空。

排序：项目，再按清单核对顺序（原始文件名、工作表、Excel 行号、行 id）。不选项目时，同一项目的块排在一起。

## 3. 一块里有什么

一块一个采购对象，在表上是连续的若干普通行。每一行都带对象身份（供应商、项目、分类、物料编码、对象零件号、对象名称、单车用量、结算价）。块的最后一行是 **合计行**（行类型写「合计」），不是合并单元格。

明细只读 **这一对象自己的那张卡**。不读父总成的卡（父卡的焊接费是另一笔，加进来会双计）。卡上的材料行已经落下，不按现行 BOM 重走树。用量用卡上的 `effective_qty`，不乘身份列上的单车用量。单车用量只说明一台车有几件，不参与合并。

关联沿卡上已经指向的记录走，不再按零件号另查一条：

```text
对象卡
  → 材料明细（cost_source、line_amount、match_hint）
  → 冲压叶子：该明细用过的那条零件价（unit_cost 与明细 unit_price 同一条）
       → 零件价上的 process_fee_id / die_fee_id / gauge_fee_id / steel_price_id / scrap_price_id
  → 焊接：卡上的 welding_fee_id
```

`match_hint` 以 `dash_fallback:` 开头时，零件价按冒号后的零件号关联，行上同时写出叶子号和实际取价号。同价多条：只在 **单价相同的那些条** 里任取一条，料片和工序必须来自这一条，不能金额用一条、尺寸用另一条。单价不同：材料列和冲次列空，备注列出各工厂单价；这条在卡上已是 `missing`。

| 对象 | 块内列什么 | 合并成什么 |
|------|------------|------------|
| 冲压件 | 它自己这一件叶子的材料明细 + 加工费各序 | 这一件的原材料、加工费、冲压件成本 |
| 退化供货件 | 卡上每一条冲压叶子的材料明细 + 各序加工费。孩子不是采购对象，不另起一块 | 各叶子加总，回到这个 L0 |
| 分总成 | 卡上 `cost_source=stamping` 的叶子：材料明细 + 加工费。本对象自己的焊接费按子表逐行 | 冲压部分合计 + 焊接费合计 |

年度价叶子（`annual`）不占用长宽厚和冲次列，金额写在外购费用合计，并带年度价 id。一口价（`bundle`）一行金额。被一口价包住的下级（`skipped_by_bundle`）仍各留一行，金额 0，写明包在哪个零件号上，避免看成缺价。`missing` 留一行，备注写匹配键，金额空。

拼焊件：材料按子片多行关联列出（各片材质、料厚、长宽）；工序仍挂父件，只列一套。该叶子的原材料成本抄父件零件价上的 `material_net_per_part`，子片行不再加一次。

## 4. 明细怎么关联

每条明细带追溯键：零件价 id、`process_fee_id`、`die_fee_id`、`gauge_fee_id`、`steel_price_id`、`scrap_price_id`、焊接费 id、来源 Excel 文件名与行号。id 还在就指向那一行；记录已经删了，格子留空，备注写「记录已不存在」，快照上的金额仍抄零件价。钢价的基价和加减价不在本表再拆，那一页是计算过程。

### 4.1 冲压材料（要关联到零件价）

一条冲压叶子至少一行材料。列从 **该条** 零件价抄，不另查：

| 列 | 来源 |
|------|------|
| 长 / 宽 / 厚 / 可制件数 | `sheet_length` / `sheet_width` / `thickness` / `parts_per_sheet` |
| 单件毛坯消耗定额 | `blank_weight_kg` |
| 材质 | 零件价 `material` |
| 产品净重 / 材料利用率 / 废料重量 | `finished_total_kg` / `material_utilization_pct` / `scrap_weight_kg` |
| 废料价格（元/kg） | `scrap_ton_price / 1000` |
| 摆剪 | 有摆剪时写 `swing_shear_fee_per_ton`（元/吨）。钢板单价里已经含过 |
| 钢板单价（元/kg） | `(steel_ton_price + swing_shear_fee_per_ton) / 1000` |
| 原材料成本 | `material_net_per_part`（单件） |
| 引用 | 空 |

同一行还要带出零件价上已经分开的三项，用来核对原材料净成本，不重算：

```text
① material_amount_sheet
② loss_scrap_deduction
③ process_scrap_deduction
原材料净成本 = ① − ② − ③
```

普通件对不上就在该叶子标「还原不符」。利废件的净成本是净重 × 废料价，①②③留空，不套上面这三条。叶子零件号写在材料行；对象零件号留在身份列。

### 4.2 冲压费用，以及叶子小计

紧跟该叶子的材料行，一序一行。工序从 `process_fee_id` 那张加工费的子表来：

| 列 | 来源 |
|------|------|
| 冲压模式 | 零件价 `automation` |
| 冲压工序 / 机台吨位 / 单冲费用 | `process_code` / `resolved_tonnage` / `line_fee`。继承吨位的，备注写来源零件号和工序 |
| 费用总计 | 该叶子零件价 `process_fee_amount`。各序相加对不上这个数，标「还原不符」，不以各序之和改写 |

模具长宽高、掏空系数、套数、重量从 `die_fee_id` 对应的布点工序来，写在对应工序行。模具费抄零件价 `die_fee_amount`（元/件），检具费抄 `gauge_fee_amount`（元/件）。样张里的万元投资、分摊台数、模摊结算不进本表。

每条冲压叶子在工序之后加一行 **叶子小计**。分项都是零件价上的单件金额，乘卡上这条明细的 `effective_qty`：

```text
原材料净成本
+ 加工费
+ 模具费
+ 检具费
= 直接成本
+ 零件级财务费、管理费、仓储包装费、税前利润
= unit_cost
× effective_qty
= 该明细 line_amount
```

小计应等于卡上这条 `line_amount`。对不上标「还原不符」。这四项附加是零件标准成本里面的，不是对象卡上的间接费用，不写进原材料列，也不从结算价里拿掉。原材料净成本 + 加工费可以另有一列，只供对照，不拿它当叶子小计，也不拿它当结算价。

### 4.3 本对象的焊接费

只列卡上 `welding_fee_id` 那一张的子表。分总成、退化供货件、冲压件同一规则。没有这张记录：焊接费为 0，备注写「无焊接核算记录」，不算断链。不把下级对象的焊接费加进来。

| 列 | 来源 |
|------|------|
| 焊接名称 / 数量 / 单价 | `standard_process_name`（空则 `process_token`）/ `process_qty` / `unit_price` |
| 行金额 | `line_fee`。数量不乘装配用量 |
| 电泳面积 / 电泳费用 | 标准工艺是电泳的行写进电泳列；其余行写进焊接列 |

`unmapped` / `missing_price` 的行照列，状态写在备注。焊接费头的层级和对象节点层级不同：仍用这一张的金额，备注写明两边层级。

各行 `line_fee` 之和应等于焊接费头上的 `total_welding_fee`。`other_fee` 单独一行，不并进上面的合计。确认金额 `final_welding_fee` = 系统合计 + 其它费用，对象卡的 `welding_amount` 抄的就是这个确认金额。

外购标准件、包装物列留空。包装在间接费用里，不进结算价。

## 5. 合计行

一块的最后一行，行类型为「合计」。对象身份列照写。合计对的是 **这一对象一张卡** 上的结算价，不乘单车用量。

| 格 | 怎么填 |
|----|--------|
| 原材料成本 | 各叶子小计里的原材料净成本（已乘 `effective_qty`）之和 |
| 费用总计 | 各叶子小计里的加工费之和 |
| 原材料加加工费 | 上两格相加。只供对照，不是结算价 |
| 外购费用合计 | 卡上 `annual` 与 `bundle` 的 `line_amount` 之和。`skipped_by_bundle` 不加 |
| 焊接费用合计 | 焊接子表 `line_fee` 之和，即 `total_welding_fee` |
| 零件单价 | 对象卡 `total_amount` |

对照写在合计行。不相等标「还原不符」，不改卡上的数：

```text
各叶子 line_amount 之和          =  对象卡冲压来源金额
外购费用合计中的年度价            =  purchased_amount
外购费用合计中的一口价            =  bundle_amount
以上三项                         =  material_amount

焊接费用合计 + other_fee         =  final_welding_fee = welding_amount
material_amount + welding_amount + welding_other_fee  =  total_amount
```

`welding_amount` 已经含了其它费用，卡上的结算价又加了一次 `welding_other_fee`。合计行照这张卡的恒等式写，不在报表里改成只加一次。其它费用那一行旁边注明「结算价中另计一次」。

## 6. 查询页与导出

「成本还原 → 采购对象」是一张查询表。先按条件查出表格，再按**同一组条件**导出。分页按采购对象计：一页是若干个对象，每个对象的明细行都在这一页里。不按表格行数分页，也不把一个对象拆到两页。

### 6.1 条件

筛选条上的条件就是 §2 的范围：

| 条件 | 是否必填 |
|------|----------|
| 基地 | 必填 |
| 年、月 | 必填 |
| 项目 | 可空。空 = 该基地全部项目 |
| 供应商 | 可空。空 = 含未指定 |

打开时，基地、年、月带出最近一次总成核价；项目带出那次的项目，可以清空。改条件后重新查询，表格换成新结果。

### 6.2 表格

普通表，一行一条明细。对象身份在每一行重复。材料、工序、叶子小计、焊接各自占行，行类型写明。每个采购对象的最后一行是合计。列与 §4、§5 相同。「还原不符」写在备注列。不合并单元格。

`page`、`size` 都按采购对象计。`size` 是本页对象个数，`total` 是当前条件下的对象个数。返回的行是这些对象的全部明细（含合计行）。

该月没有命中：空表。没有清单：不查，提示「请先生成采购对象清单」。

### 6.3 按条件导出

导出把当前筛选条件下的全部采购对象写成一本 xlsx，列与查询表相同，不再取一遍数。不带 `page`、`size`。不照原 Excel 排版。

| 项 | 规则 |
|----|------|
| 没有清单 | 与查询同一句拒绝 |
| 该月没有命中行 | 仍下载。表上只有表头 |
| 检测未通过 | 允许下载。第一行注明未通过 |
| 工作表 | 一本一个表，表名「采购对象」。一行一条明细，不合并单元格 |
| 单元格 | 金额、重量、用量写数字。不加盖水印 |
| 文件名 | `成本还原-采购对象-{基地}-{年}年{月}月.xlsx`。选了项目，项目写在基地后面 |
| 权限 | `op:cost-restore-procurement-object:export`。没有该权限，表格上不显示导出，接口拒绝 |

## 7. 落地位置

查询表。打开按 §6.1 的默认条件查出第一页采购对象。导出用表格上当前的基地、年、月、项目、供应商，不含页码。

### 7.1 代码

放在 `costing` 切片里，单独目录，不塞进 `assembly_cost` / `procurement_contract_report`：

```text
app/routers/costing/cost_restore/procurement_object.py
app/services/costing/cost_restore/procurement_object/service.py
static/js/features/costing/cost-restore/procurement-object/
```

页键 `cost-restore-procurement-object`。计算过程仍是 `/assembly-cost-restore`，本页不复用那条路由。

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/costing/cost-restore/procurement-objects` | 查询。基地、年、月必填，项目与供应商可空。`page`、`size` 按采购对象计，返回这些对象的全部明细行 |
| GET | `/api/costing/cost-restore/procurement-objects/export` | 与查询同一组条件，不带页码。返回整本 xlsx，见 §6.3 |

Service 先装出与列表相同的块，导出只负责写入工作簿。不调 Parser，不写库，不开计算任务，不再做一套对象分类，不重走 BOM。

### 7.2 菜单

与「核价」「采购价格协议」平级，单独一组。组本身不能点进页面。

```text
成本还原
  └── 采购对象
```

| 节点 | 码 | 类型 |
|------|----|------|
| 成本还原 | `menu:cost-restore` | group |
| 采购对象 | `menu:cost-restore-procurement-object` | menu |
| 查询 | `op:cost-restore-procurement-object:view` | op |
| 导出 | `op:cost-restore-procurement-object:export` | op |

落地时写入 `catalog.json`，并接到侧栏和 `pageMeta`。不挂到 `menu:costing` 下面，也不挂到总成核价组。以后若再加别的还原页，仍挂在「成本还原」下，不另开一组。

## 8. 做 / 不做

| 做 | 不做 |
|----|------|
| 基地 + 年月必填；项目可空，空则该基地全部项目 | 不选项目就把不同基地打进一张表 |
