# 年度协议价生效期 — 设计说明

> 状态：**已否决（不做）**  
> 决定：2026-09-23。年度协议价保持一年一行。年中改价仍走现网：反审后覆盖。不给一口价、焊接单价、包装运输费、吨位价加起止月。  
> 下文是否决前的分段方案，仅作存档。若再有人提「8 月改价不能覆盖 1–7 月」，先读本节，不要按下文改表。  
> BOM / 冲压工艺 / 模具行上的生失效是另一篇，已经落地，见 [bom-process-die-effective-period-design.md](../engineering-change/bom-process-die-effective-period-design.md)。不要跟着本文一起停。

---

## 0. 一句话

> **一口价、年度外购价、焊接单价仍是「某年某基地的协议价」，不是月度行情；但一行必须带适用月范围。核价按月份取命中的那一段。年中改价 = 截断旧段、新增一段，旧单价不覆盖。**

已否决：审核时落 Excel 进文件溯源（文件补表结构，引擎读不到）。  
已否决：把协议价做成 12 条相同的月度行（把例外当成默认结构）。

---

## 1. 为什么做

现网年度零件价唯一键是 `(location, year, part_number)`，焊接单价是 `(location, year, item_name)`。一年一个价。

商务默认「当年一般不变」，和钢材「每月一议」不是一类。但年中会改口：年初一口价 1 元，8 月改成 2 元。现网只能反审整年、覆盖那一行。库里只剩 2 元。

| 谁要用数 | 现网 | 要对上的答案 |
|----------|------|----------------|
| 客户 | 列表里一年一行 | 1–7 月 1 元、8–12 月 2 元，页面能看见 |
| 核价引擎 / 成品月账 | `list_with_unit_price(location, year)`，**不看月** | 算 3 月取 1 元，算 8 月取 2 元 |
| 分析 / LLM | 按年聚合 | 能问上半年、能问 8 月起 |

成品月账（`costing_assembly_cost_items.unit_price`）在计算当时会抄单价。3 月已审核则 3 月账上仍是 1 元。一旦反审 3 月再算，引擎会再读主表，读到 2 元，口径就错。主表必须自己能按月回答，不能靠「别重算旧月」硬撑。

文件溯源继续只登记 **客户上传原件**。适用哪几个月是行上的字段，不是附件。

## 2. 粒度：年 + 起止月，不是日历日，也不是 12 行

核价、钢材、零件价、成品账的时间轴都是 **年 + 月**。协议价的生效范围对齐这根轴。

| 字段 | 类型 | 含义 |
|------|------|------|
| `year` | int | 定价年度，不变 |
| `effective_month_from` | int 1–12 | 含，这段价从哪月开始 |
| `effective_month_to` | int 1–12 | 含，这段价到哪月结束 |

展示：`2026年1月–7月`。禁止存 `date` / `datetime` 当生效期：系统没有「日」口径，8 月 15 日改价在核价里仍是 8 月，日期是假精确。

默认（导入、迁移、当年只订一次）：`from=1, to=12`，行为与现网「全年一行」相同。

同一业务键下多段：

```text
青岛 · 2026 · 零件A
  1–7 月   1.0000 元   approved
  8–12 月  2.0000 元   approved
```

规则（写在 `app/common/effective_month.py`，各切片共用，不碰 Model）：

1. `from <= to`，均在 1–12。  
2. **闭区间**。`1–7` 与 `8–12` 相邻，不算重叠。  
3. 同一业务键（见 §3）的月份 **禁止重叠**。SQLite 无 exclusion，Service 写入前校验；命中则 `BusinessException`。  
4. **允许空洞**（例如只有 1–6、没有 7 月）。核价该月缺价 → 与现网「价表无记录」相同（partial / 门禁失败），不自动用邻段填。  
5. 取价：`from <= 核价月 <= to`，至多一行；多行即数据错误，应在写入时挡住。

弱唯一键（库约束，防完全重复）：`(业务键…, effective_month_from)`。重叠仍靠 Service，不能只靠 UNIQUE。

## 3. 哪些表改、哪些不改

### 3.1 要加生效期的：年粒度协议价

| 表 | 现网唯一键 | 业务键（分段后） | 取价方 |
|----|------------|------------------|--------|
| `bom_annual_part_prices` | 基地+年+零件号 | 同左 | 成品月核价 **每月** 读 |
| `bom_welding_unit_price` | 基地+年+项目名 | 同左 | 成品焊接费计算 |
| `bom_packaging_transport_fees` | 基地+年+车型+零件号 | 同左 | 成品月核价 **每月** 读 |
| `stamping_tonnage_price` | 基地+年+吨位 | 同左 | 冲压加工费（加工费本身已按月） |

前三张直接决定成品账里的一口价 / 外购 / 包装 / 焊价。冲次单价同构，可同一套规则，实施可稍后（见 §11）。

### 3.2 不加生效期的

| 对象 | 原因 |
|------|------|
| 钢材联动、零件价、成品月账 | 已经是年+月；明细里已有计算时单价 |
| 冲压加工费、一事一议基价/政策 | 已经是月 |
| 焊接工艺拆解 | 按基地+车型+BOM 版本，不是日历价 |
| 用户上传原件 | 仍走 `file_trace`，与适用期无关 |

### 3.3 必跟：成品焊接费要从「年」改到「月」

现网 `bom_welding_fees` 按 **年 + 基地 + 车型 + BOM 版本** 存（财务读 `level=0`），引擎阶段 `annual_welding_fee`：**一年算一次，12 个月成品账共用**。

焊接单价一旦分段，这条必须改。否则 8 月焊点 2 元，成品账仍用年初算死的焊接费。

定稿：

- 焊接费 **计算入参带核价月**；结果表增加 `month`；唯一键加上 `month`。  
- 取焊接单价：`list_by_location_year_as_of_month(location, year, month)`。  
- 工艺拆解仍按版本，用量不随月变；变的是单价。  
- 引擎：焊接费从「年度一步」改为与钢材/零件价一样 **按月一步**（或每月取价重算）；已审核该月焊接费仍跳过不覆盖。

包装、一口价没有单独的「年结果表」，成品月账直接读主表，改取价即可。

## 4. 取价（程序与分析的同一条）

所有下游禁止再 `list_*(location, year)` 当核价用价。必须带月：

```text
as_of(location, year, month, business_key)
  → 命中 from<=month<=to 的至多一行
```

| 调用方 | 现网 | 改为 |
|--------|------|------|
| `L0AssemblyCost` orchestrator 的 `annual_prices` / 包装 | 只传 year | 传核价 `month` |
| 焊接费 calc | `list_by_location_year` | `as_of` 该计算月 |
| 加工费取冲次单价（冲次表落地后） | 年 | 年+月 |
| 引擎 gate | 「该年有没有年度价」 | 「该年该月有没有覆盖该月的已审核段」 |
| LLM / 分析 | 按年 | 问月则 as_of；问年则返回该年全部段，禁止悄悄用「最后一段」冒充全年 |

取价是否只认 `approved`：与现网各模块 **各自** 门禁对齐后写进 Repository 过滤条件。同一月不得两段。不要在 rollup 里 if/else 拼范围。

成品月账仍 **抄入** 当时 `unit_price`。重算某月时重新 as_of，所以主表分段后，重算 3 月仍得 1 元，重算 8 月得 2 元。这才是库能对上。

## 5. 改价：第一类操作，不是反审整年

反审核仍只用于：这段价 **整段作废重填**（导错、审错）。年中商务改口 **不要** 走反审覆盖。

新命令（名称示例）：`revise_from_month`（改价自某月生效）。

前置：

- 指定业务键 + `from_month`（8）+ 新单价 + 原因（必填）。  
- 必须存在一段已覆盖 `from_month` 且 `effective_month_to >= from_month` 的行（通常是 `1–12`）。  
- 新段 `[from_month, 旧.to]` 不得与第三者重叠。  
- `from_month == 1` 且旧段就是 `1–12`：这是改全年，应走普通改价/反审，不走「截断」。

同一事务：

1. 旧段 `effective_month_to = from_month - 1`（8 月生效 → 旧段变为 1–7）。**单价、审核状态不变。** 已审核段允许只改止月，这是本命令的唯一例外，不是解锁改价。  
2. 插入新段：`from=from_month, to=原 to`，新单价，`pending`，原因写入 `remark` 或专用字段。  
3. 重叠校验。  
4. `commit`。

之后：新段走现网审核。旧段 1–7 仍是已审核 1 元。

| 已有月度账 | 行为 |
|------------|------|
| 1–7 月成品已审核 | 不动。抄入的仍是 1 元 |
| 8 月及以后已审核 | **不自动反审、不改数。** 页面提示：主数据 8 月起已是 2 元，该月成品账仍是旧数，要对齐请反审该月成品后重算 |
| 8 月未算 / 未审 | 下次计算 as_of(8) 得 2 元 |

禁止：改价成功却把 1–7 的已审核成品重算掉。

列表提供「改价」入口（操作列按钮，禁止整行点击）。批量：同一基地+年、同一 `from_month`，可对勾选零件出新段（一期可先做单行，批量放二期）。

## 6. 导入 / 审核 / 列表

### 6.1 导入

模板增加可选列 **生效起月、生效止月**。空则 1 和 12。

同一文件允许同一零件两行（1–7 与 8–12）。Parser 校验范围与文件内重叠。

写入规则：

- 匹配键：业务键 + `effective_month_from`（与弱 UNIQUE 一致）。  
- 命中且已审核 → 跳过不覆盖（与现网相同）。  
- 与已有段 **月份重叠但 from 不同** → 整单或该行拒绝，文案写明重叠月份。禁止导入一张「全年 1–12」把已存在的 8–12 默默盖掉。  
- 钢价「无有效行也归档原件」的规则不变；本表按现网年度价 import 行为，只是多两列。

客户仍一年给一张协议价 Excel。年中改口：优先用系统「改价」，不必为了 8 月再传一张全年覆盖表。

### 6.2 审核

审核粒度 = **段**，不是「这个零件今年」。可按现网「基地+年」批量审，但只更新该范围内待审行；已通过的 1–7 段跳过。

反审某段：只把该段打回 pending。不得级联删除另一段，不得自动把邻段 `to` 拉长（避免 1 元悄悄变回全年）。

### 6.3 列表与导出

- 列：适用期（`1–12月` / `8–12月`）。同一零件多行。  
- 筛选：现有基地/年之外，增加「核价月」：只显示覆盖该月的段（给对账用）。  
- 导出：带起止月；从库表倒出，不是审核快照。  
- VO 增加 `effective_month_from` / `effective_month_to`；JSON 仍是 int，不要格式化成日期字符串冒充日口径。

## 7. 分层与公共规则

```text
切片 Service（改价 / 导入重叠 / 审核）
    │  用
app/common/effective_month.py     # 纯函数：合法范围、是否重叠、是否覆盖某月
    │
切片 Repository.as_of_month(...)  # 只拼 SQL，不做「该不该改价」
```

`common/` 不得 import `bom` / `costing`。重叠策略判断（拒绝 vs 截断）在 Service。  
`revise_from_month` 放在各价表自己的 Service，不要在 Router 里拆段。  
costing 只调用上游 Repository/Service 的 `as_of`，禁止 costing 自己实现一套月份比较。

## 8. 与月度结果、原件的关系

```text
协议价主表（分段）     ← 客户看见的「哪几个月多少钱」
        ↓ as_of(月)
成品/加工费/焊接费月结果  ← 该月账；已审核则引擎不覆盖
        ↑
客户上传 Excel           ← file_trace 原件；supersede 仍按「这次传的文件」
```

三套不要合成一套。原件会被新上传 supersede，**不能**当 1 元历史。月结果是该月快照字段，**不能**替代主表分段（否则没算过的月、分析问主数据时仍对不上）。主表分段是协议价的账本。

## 9. 明确不做

| 非目标 | 原因 |
|--------|------|
| 审核落盘 Excel 当历史 | 引擎/分析不读文件；已否决 |
| 默认拆成 12 条月行 | 协议价不是行情；导入和漏月会出问题 |
| 生效日起止（日） | 无日口径 |
| 跨年一段（2026-11 到 2027-02） | `year` 仍是定价年；跨年是下一年的段 |
| 改价自动重算已审核月度账 | 月账锁定规则不变 |
| 反审自动合并邻段 | 防止价格悄悄变回全年 |
| 一期改冲次单价（可同规则后做） | 先打通一口价/包装/焊接这条成品链 |

## 10. 数据迁移

现网每一行：`effective_month_from=1, effective_month_to=12`。语义与现在「全年」相同。

1. 加两列，NOT NULL，默认 1 和 12。  
2. 删旧 UNIQUE，建新 UNIQUE（业务键 + `effective_month_from`）。  
3. 回填无需猜历史改价：库里本来就没有第二段，不能造假历史。  
4. 取价接口未改完之前不要先让导入写出非 1–12 的段（否则成品仍按年读会重复零件键、后写覆盖或不确定取哪行）。**迁移列与 as_of 取价同一期上线。**

## 11. 实施顺序

1. `app/common/effective_month.py` + 单测（重叠、相邻、空洞、非法 0/13）。  
2. **年度零件价**：列、改 UNIQUE、Repository `as_of`、改价命令、导入两列、列表适用期、成品核价 orchestrator + gate + LLM 取价改月。  
3. **包装运输费**：同 2（成品月账已在读）。  
4. **焊接单价分段** + **焊接费结果加 month** + 引擎年度焊接费步骤改按月。  
5. （可选）冲次单价分段 + 加工费取价带月。

不要只改表结构、取价仍按年——那比现在更坏（同一零件两行，dict 按零件号后写覆盖）。

## 12. 验收（对业务）

> 青岛某件 2026 年初审过 1 元（1–12）。8 月「改价自 8 月生效」为 2 元并审核。列表能看到两段。算 3 月成品用 1 元，算 8 月用 2 元。3 月已审核账不变。分析问 3 月一口价是 1 元。文件溯源不必为此多一份审核 Excel。

| 场景 | 通过 |
|------|------|
| 默认导入 | 不起止月 → 1–12，与现网一年一行一致 |
| 改价 8 月 | 旧段 1–7 仍 approved 且 1 元；新段 8–12 pending→approved 且 2 元 |
| 成品 3 月 / 8 月 | as_of 分别 1 元 / 2 元 |
| 重算 3 月 | 仍 1 元（不是 2 元） |
| 导入 1–12 撞上已有 8–12 | 拒绝，不覆盖 |
| 反审 8–12 段 | 1–7 段仍在 |
| 焊接（步骤 4 后） | 8 月焊接费用 8 月段单价，不共用年初一次算的年结果 |
