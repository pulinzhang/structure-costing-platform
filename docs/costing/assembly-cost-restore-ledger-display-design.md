# 计算过程 — 总成（商务）与采购对象（采购）

> **状态：已落地。** 只改计算过程报告的**叙述与分总成节点加数**。不算第二遍价，不新建结果表。  
> **读者：总成给商务看，采购对象给采购看。** 报告正文只用这两岗的词，不用财务/会计黑话。第一目标是降低**新商务、新采购**的认知负担。打开 30 秒内应能回答「右上角是给谁的价、树上这笔含不含焊装」。  
> 切片：`costing` / `assembly_cost` / `restore`。公式仍只认 [assembly-costing-design.md](assembly-costing-design.md)（尤其 P21）。  
> 载体仍是 [assembly-cost-restore-design.md](assembly-cost-restore-design.md) 的浅色画册页。  
> 入口不变：总成核价一览、采购价格协议（**总成 / 采购对象**）点「计算过程」→ `/assembly-cost-restore?...`。

## 0. 一句话

**协议页与核价一览不改。** 计算过程按入口分岗：

- **商务**打开的是 **总成**：给主机厂的**一台份**价格。
- **采购**打开的是 **采购对象**：给供应商的**结算价**。

一页只证明其中一个数。总成树上的分总成不要画成采购对象结算价（材料+焊装），否则商务会以为总成价漏加或加重了。

**两页数字本来就不该一样。** 原因只有一句，写进报告：

> 总成的焊信上已经包含所有分总成焊信。

## 1. 读者与认知预算（硬约束）

落地后用这两个人验收，**不要用熟悉现网的人验收文案**。

| 读者 | 从哪进来 | 只允许他记住 |
|------|----------|----------------|
| 新商务 | 协议「总成」；总成核价财务一览 | 右上角 = 给**主机厂**的**总成价**（一台份）。树上分总成 = **材料**。焊装只看「本总成焊装」。和采购对象页数字不同是规则，不是漏报。 |
| 新采购 | 协议「采购对象」；总成核价采购一览；或从总成树上点「采购对象」 | 右上角 = **结算价**（给供应商，价格构成含焊装）。不要求他在这页读总成焊信。 |

**一页只加一个数。** 另一岗的价只以链接「采购对象」出现，**不以第二个大金额出现**。树上再印「结算价另含焊装 ¥x」会诱导相加，视为失败。

**为什么对不上，印在总成报告上。** 采购对象页禁止再讲一遍总成焊信。

报告正文禁用（实现注释除外）：会计、财务、成品账、采购应付、核价卡、L0、L1、P21、`should_cost`、树根、本对象、兄弟卡、一台价、一件价。

对外只用：**商务 / 采购 / 总成 / 采购对象 / 分总成 / 主机厂 / 供应商 / 一台份 / 结算价 / 材料 / 焊装**。

句子：**主路径零教育。** 封面、价格构成、焊装章只摆账。对照原因只出现在总成「零件构成」里一条默认收起的「为什么分总成只计材料」。采购对象页连这一条都没有。不要专章、对照表、封面导语。

## 3. 两岗两页（报告怎么自称）

同一张核价结果、同一套公式。`view` 只换**封面强调列与文案**，不换还原规则。

| URL `view` | 谁点进来 | 右上角（系统列） | 对外怎么说 |
|------------|----------|------------------|------------|
| `finance`（缺省） | 商务：协议「总成」；一览财务视图 | `grand_total` | **总成价**（一台份，给主机厂） |
| `procurement` | 采购：协议「采购对象」；一览采购视图；总成树上点「采购对象」 | `total_amount` | **采购对象结算价**（给供应商） |

协议页现网已按视图带 `view`（总成 → `finance`，采购对象 → `procurement`）。本设计不改该映射。

封面 `highlight_label`：商务页不要写「总费用」（会计词）；采购页不要写「总成本」（账套词）。分别改为 **总成价**、**结算价**（若改标签会影响现网封面，落地时只改计算过程这一页的展示文案）。

两岗数字为什么不同，印在总成报告即可。采购对象页按结算价自己读，不对照总成。仍禁止同一屏摆两笔焊装让人加。

## 4. 文案（写死，实施时不要再润色成长文）

语气：商务、采购开会能直接念出来的句子。

### 4.1 封面（`coverHtml`）

**两岗都不出教育导语。** 商务靠右上角 **总成价**，采购靠 **结算价**。熟手每天打开，封面只留短码和金额。

徽章仍写 **计算过程**。不要加「商务」「采购」徽章。

页签 `<title>` **维持** `{part_number} {year}年{month}月计算过程`。

### 4.2 价格构成（`waterfallHtml`）

商务：原「焊装」改为 **本总成焊装**。末行对外标签 **总成价**（对应 `grand_total`；现网「总费用」仅内部）。中间「月总账」若出现在商务页，改为 **未摊入前** 或并进构成、不单独用会计科目名——能删则删，以免商务问「月总账是不是给主机厂的价」。摊入费用仍可保留（商务要看一台份是否含包装分摊）；标签用 **摊入费用**，不要「间接」。

采购：焊装标签仍是 **焊装**。末行 **结算价**（对应 `total_amount`）。不要写「本总成焊装」「总成价」（采购不在报一台份）。

### 4.3 焊装章（`weldingHtml`）

无教育导语。直接焊信原文与明细。无记录：维持现网「无焊装」。禁止用下层焊接费来「补」本章。原因不在本章重复，只在 §4.5 一处。

### 4.4 树上的链接

| 节点 | 现网 | 改为 | 用意 |
|------|------|------|------|
| 分总成（`cost_source=sub_assembly`） | 「计算过程」 | **采购对象** | 和协议开关同一个词；商务知道点过去是采购在看的那一页 |
| 自制冲压 | 「计算过程」 | 仍「计算过程」 | 冲压件也是采购对象，但不是「总成 vs 采购对象」这组对照 |
| 外购 / 一口价 | 无链接 | 仍无 | |

分总成链接仍开新页签，`view=procurement`。不要整行跳转。

### 4.5 分总成为什么和采购对象不一致（按需展开）

发生地点：商务看的总成报告里，**有**分总成节点时。放在零件构成树**上方**，`<details>` **默认收起**。

- 摘要（始终可见、细字）：`为什么分总成只计材料`
- 展开后（只此一次）：

```text
总成的焊信上已经包含所有分总成焊信。采购对象结算价另含焊装，两页不能加在一起。
```

熟手扫过摘要即可。新手怀疑漏焊装时自己点开。禁止印在封面、焊装章、采购对象页。禁止在旁边印结算价数字。无分总成节点：整块不出。一口价分总成不要套用这句。

## 5. 分总成节点：总成价计入 ≠ 采购对象结算价

### 5.1 现网问题

有采购对象核价结果时，分组节点现用：

```text
unit_price   = sibling.total_amount      // 材料 + 焊装 + 焊接其它
line_amount  = unit_price × path_qty
```

再画出「材料 / 焊装 / 总成本」。商务在总成报告里看到分总成也有焊装，会以为总成价漏报或已含采购结算。采购从总成树点进来，会对不上协议上的采购对象结算价。

分组节点只是画树用。封面往往仍对，**树上却在教错误加法**。

### 5.2 加数（任意 `view`）

子孙分总成节点的行金额 = **本页材料 walk 在该子树上的贡献**：

```text
line_amount = Σ 本卡 items.line_amount
              其中 item 是该 BOM 节点的后代
              且 cost_source ∈ {stamping, annual, bundle}
              （skipped_by_bundle / missing 不加）

unit_price  = line_amount / effective_qty    // qty=0 则 0
```

禁止用采购对象卡 `total_amount` 当 `unit_price` / `line_amount`。不要再查兄弟卡、不要下发 `assembly_welding_amount`。

无采购对象卡：同样按本页后代材料加总。一口价仍是 `bundle`；剪枝子孙仍 0。

### 5.3 展开块

子孙分总成没有「材料 / 焊装 / 结算价」构成块。行右金额 = §5.2 `line_amount`。要看付给供应商的结算价，只点「采购对象」。

### 5.4 冲压叶子的「其它费用」

叶子仍还原 `unit_cost`（净材料、加工、模具、零件级附加）。这些已进本页材料，与采购对象焊装无关。不改 `stampingBlock`。封面禁止写「总成只用材料费」——商务会以为冲压加工没进总成价。

## 8. 测试

1. **总成还原（finance）**：下层分总成有焊装时，树上该节点 `line_amount` = 本卡该子树 `stamping+annual+bundle` 合计，**不等于**采购对象卡 `total_amount × qty`。
2. 封面恒等式仍与落库列相符。
3. **采购对象还原（procurement）**：封面强调结算价（`total_amount`）；焊装章是这件自己的费行。
4. 一口价剪枝子孙仍 0。
5. 无采购对象卡的分组节点不 500。

手工（找新商务、新采购各一人，**不许旁边讲解**）：

- 商务只打开总成计算过程：能说出右上角是给主机厂的总成价；展开分总成看不到第二笔焊装金额；能根据印出的句子说出「外发采购对象才含焊装、总成焊信已经含过、不能加进总成价」。
- 采购只打开采购对象页：能说出右上角是结算价、已含焊装，且总成那页只计材料不是漏算。
- 总成树上点「采购对象」进的是采购那一页。
