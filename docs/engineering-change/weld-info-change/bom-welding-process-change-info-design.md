# `bom_welding_process_change_info` — 设计

> 状态：**设计定稿，未落地。**
> 本篇只处理焊信变更。主表 `bom_welding_process_change_info` 记是否有焊信、时间和焊接费。明细 `bom_welding_process_change_info_lines` 从焊接单价里选项目、录入数量，并记下金额。头上的焊接费是明细金额之和；无焊信时为 0。不改节点、拆解明细、年账。
> 保存后的行交给下游读。不审核，不另做权限。下游怎么取数、怎么计价，另文。第一个下游是 [抄焊接费](welding-fee-resolve-design.md)。目录见 [焊信变更](README.md)。
> 模型放在 `app/models/bom/`，与 `welding_process_breakdown.py` 并列。写入在 `app/services/bom/welding_process_breakdown/`。

---

## 0. 一句话

一次变更是一张主子表。头上是这段的开始、结束、是否有焊信，以及焊接费。有焊信时，明细从 `bom_welding_unit_price` 里选：基地对这个节点的基地，年度对头上的开始年；数量必须录入，金额是数量乘当时单价。头上的焊接费是这些金额之和。无焊信时明细为空，头上的焊接费为 0。节点上的 `weld_info_raw`、拆解明细、SOP 年账都保持不动。

---

## 1. 为什么单独立项

| 现有通道 | 它回答的事 | 焊信变化对不上的原因 |
|----------|------------|----------------------|
| 树的生失效 | 这棵总成这个月还在不在 | 截断树会把仍在供货的零件从冲压、结构、采购里一起拿掉 |
| 设计变更 | 互换性变了，换成新零件号 | 停电泳通常不换号。新树的拆解是从旧树整套抄的，节点焊信还是旧的 |
| 材料变更 | 同号、只改材料 | 焊信不是材料 |
| 拆解明细 | SOP 原文拆出来的过程量 | 焊信变更不改这些行，也不以这些行为底稿 |

年账仍是一年一行。月与月的差异记在本表。协议价年内分段已否决，见 [effective-period-design.md](../../costing/effective-period-design.md)。

        │
        ▼

        │

| 谁 | 做 | 不做 |
|----|----|------|
| 拆解列表 | 每一行一枚「焊信变更清单」，打开该节点的变更列表 | 在拆解列表上弹框；把这一页放进侧栏；改节点 `weld_info_raw`；改材料清单焊信；改树的生失效；改拆解明细 |

下游不写这两张表。它们读什么，见 §7。

## 3. 表

两张表，主子关系。头挂在拆解**节点**上。选哪条焊接单价、数量和金额只在明细里。不引用 `bom_welding_process_breakdown_line`。

```text
bom_welding_process_breakdown_node          现网 SOP 节点（weld_info_raw 仍是投产焊信）
 └── bom_welding_process_change_info        头：是否有焊信、开始、结束、焊接费
      └── bom_welding_process_change_info_lines   行：单价、数量、金额
```

`bom_welding_process_breakdown_line` 仍只服务于 SOP 拆解和 SOP 年账。焊信变更不插入、不更新、不删除那些行。

头 Model 可以 `relationship` 明细，也可以 import 明细 Model。删一条变更只碰这两张表。

### 3.1 头 `bom_welding_process_change_info`

挂 `breakdown_node_id` → `bom_welding_process_breakdown_node.id`，`ondelete="RESTRICT"`，`onupdate="RESTRICT"`。节点上还有头时，拆解不能删、整包生成不能清掉该节点。

| 列 | 对人说法 | 规则 |
|----|----------|------|
| `breakdown_node_id` | 哪一条拆解节点 | 必填 |
| `start_year` / `start_month` | 开始 | 必填。含本月 |
| `end_year` / `end_month` | 结束 | 同空或同有。空 = 未结束。有则含本月，且不得早于开始 |
| `has_weld_info` | 是否有焊信 | 布尔。真 = 明细至少一行。假 = 无焊信，明细必须为空 |
| `welding_fee` | 焊接费 | `Numeric(14, 4)`。有焊信时等于明细 `amount` 之和。无焊信时为 0。服务写入，调用方不算 |
| `remark` | 原因 | 可空。例如「取消电泳」 |

头上没有审核状态，也没有审核人、审核意见、反审核。创建人、更新人与拆解节点一样走 `AuditUserMixin`。

基地、项目、零件号、层级不在头上再存一份。要显示时 join 拆解节点。

硬唯一：`(breakdown_node_id, start_year, start_month)`。同一节点不能有两段从同一个月开始。跨月重叠靠 Service 挡住。

开始、结束都写在头上。上一条是该节点上、除正在保存的这条以外，开始最晚的那一条。新增时就是现有记录里开始最晚的那条。

新增一条时，若上一条的结束还空着，服务把上一条的结束写成新一条开始的前一个月。上一条结束已经有值，则不动。新开始是 1 月时，这个结束是上一年 12 月。

只有开始最晚的那一条可以编辑，也可以改开始年月。更早的一条不允许编辑，也不允许删除。保存后若开始年月有改动，同一事务里把上一条的结束写成新开始的前一个月；上一条结束已经有值也要改。没有上一条则不改。

删掉开始最晚的一条后，剩下的记录里开始最晚的那条，结束改回空（未结束）。树后来到期或被设变截短，也不回写这一头。

### 3.2 明细 `bom_welding_process_change_info_lines`

挂 `change_info_id` → `bom_welding_process_change_info.id`，`ondelete="CASCADE"`，`onupdate="CASCADE"`。删头时明细一起走。明细不指向拆解节点。

| 列 | 对人说法 | 规则 |
|----|----------|------|
| `change_info_id` | 哪一条变更 | 必填 |
| `line_no` | 行序 | 从 1 起，同一头里不重复 |
| `unit_price_id` | 哪一条焊接单价 | 必填。指向 `bom_welding_unit_price.id`，`ondelete="RESTRICT"`，`onupdate="RESTRICT"` |
| `qty` | 数量 | 必填。整数，必须大于 0。不是整数则拒绝 |
| `amount` | 金额 | `Numeric(14, 4)`。保存时 `qty ×` 该单价行的 `unit_price`，按单价表的四位小数写入 |

同一头下，同一条焊接单价只记一行。

选项是 `bom_welding_unit_price` 里、`location` 等于该拆解节点基地、`year` 等于头上开始年的行。单价表不按项目号分，基地就是这个节点所属项目的基地。选中的行必须同时满足这两列，否则拒绝。

数量由用户录入，必须是大于 0 的整数。项目名称、单位、单价从选中的那一行带出，用来展示，不在明细里再抄一份。单价表的 `unit_price` 是四位小数，明细金额和头上的焊接费也是四位小数。单价表以后改价，已写下的 `amount` 和 `welding_fee` 不跟着变，直到这条变更再次保存。

结束年晚于开始年时，这一头仍用开始年的单价。下一年的价另记一条头。

## 4. 写入

从拆解列表这一行点「焊信变更清单」进入。打开后先是这一节点已有的卡片。节点就是这一行，不再另选。不看这颗拆解节点自己审没审。新增或编辑在弹框里填开始、结束、原因，并二选一：

| 选择 | 用户做什么 |
|------|------------|
| 有焊信 | `has_weld_info` 为真。从该基地、开始年的焊接单价里选一行或多行，每行录入数量 |
| 无焊信 | `has_weld_info` 为假。不选单价，不填数量。明细为空，头上 `welding_fee` 为 0 |

保存即生效，不经审核。一次写入头和它的明细。保存不调用 Parser。金额由服务按当时单价计算，保留四位小数。

1. 拆解节点必须在，且 `source_node_id` 能走到 L0 树根。走不到则拒绝。
2. 开始年月必填，月 1–12。结束同空或同有；有则不得早于开始。
3. 开始月必须落在**当时**树根寿命里。结束若有，结束月也必须落在当时树根寿命里。结束空着不把树的失效月写进本行。树以后被截短，本行保持原样。
4. 同一节点上，其它记录与本段有任一重叠月 → 拒绝。更新时排除自己。结束空着的记录，从开始月起往后每个月都算占着。上一条见 §3.1。新增时若上一条结束空着，先把它写成新一条开始的前一个月，再做这次重叠检查。上一条结束已有值时，新增不改它。新开始是 1 月时，写上的结束是上一年 12 月。这个前一个月早于上一条的开始，或落不进当时树根寿命，则整单拒绝，上一条结束保持原样。相邻可以：上一段结束在 6 月，下一段开始在 7 月。补写和新建在同一个事务里，新建失败则上一条结束也不改。
5. `has_weld_info` 为真时，至少一行明细。每一行的 `unit_price_id` 必须存在，且该行 `location`、`year` 分别等于节点基地和头上开始年。`qty` 必须是大于 0 的整数。同一头里不能有两行指向同一条单价。`amount` 按当时 `unit_price` 重算，保留四位小数。头上 `welding_fee` 等于各行 `amount` 之和。为假时，明细必须为空，`welding_fee` 写 0。
6. 改了开始年，原来的明细若对不上新年度的单价，整单拒绝，须重选。
7. 只有开始最晚的那一条可以编辑。更早的一条，编辑整单拒绝。编辑这条最新记录且开始年月有改动时，把上一条的结束写成新开始的前一个月，上一条结束已有值也改；再做重叠检查和第 3 条。没有上一条则只改这一条。前一个月早于上一条开始，或落不进当时树根寿命，整单拒绝，两条都不改。改写和保存这一条在同一个事务里。

只有开始最晚的那一条可以删除。不是最新的一条不允许删除，文案说明须先删后面的焊信变更。删除只删这个头，明细因 `CASCADE` 一起删除。删掉之后，剩下的记录里开始最晚的那条，结束改为空，卡片上显示「未结束」。更早的结束不动。本节点已经没有记录时，不再改结束。删头和改结束在同一个事务里。不改节点、拆解明细、年账。

总成格子是财务认的那一笔。电泳写在总成焊信上，记录就加在总成这个拆解节点上。下级节点自己的焊信要变，在下级节点上另加一条。

## 5. 页面与 API

变化少，不做 Excel 上传。不进侧栏。入口仍是现网拆解列表 `#/bom-welding-process-breakdown-list`。

每一行操作列，在「查看明细」「编辑明细」旁边再放一枚，文案「焊信变更清单」。同一套操作列图标按钮。点这一行，进入新页 `#/bom-welding-process-change-info?node_id=` 该节点 id。节点已审核时，「编辑明细」不可点；「焊信变更清单」仍可点，因为改的是辅助表，不动节点和明细。

新页只处理这一个节点。打开就是这一节点的卡片列表：上面是基地、项目、零件号、层级，和一枚「新增」；下面按开始年月从早到晚，一张卡片一条变更。不再选节点。地址只带 `node_id`，不因弹框改地址。没有 `node_id`，或节点不存在，回到拆解列表。页上提供返回拆解列表。

没有变更时下面是空的，只留这枚「新增」。不分页。焊信变更很少，一次列出该节点的全部卡片。不用表格，也不做单独的查看。

每张卡片展示这条的开始、结束（空显示「未结束」）、是否有焊信、原因、焊接费，以及按 `line_no` 排列的明细：项目、单位、单价、数量、金额。开始、结束用现网 `fmtPeriod`。焊接费和金额展示四位小数。无焊信的卡片没有明细，焊接费为 0。项目、单位、单价来自选中的焊接单价行，只展示。

卡片留在后面。新增、编辑是盖在卡片上的弹框，不用抽屉，也不整页换成录入。没有查看弹框。

| 动作 | 在哪 | 做什么 |
|------|------|--------|
| 新增 | 卡片列表上方，只有一枚 | 弹框，空白录入 |
| 编辑 | 只有开始最晚的那张卡片 | 弹框，带上这一头和明细。更早的卡片不提供编辑 |
| 删除 | 只有开始最晚的那张卡片 | 不打开录入弹框。确认后删这一头，并把剩下最近一张的结束改成「未结束」。明细随 CASCADE 删除。更早的卡片不提供删除 |

关掉弹框仍是原来的卡片。保存成功后关掉弹框，并刷新卡片。这条变更不属于当前节点时，不打开弹框。

没有审核，没有反审核。

新增和编辑的弹框里：先定开始年，再选该基地、该年的焊接单价，并录入数量。单价、单位从选中行带出，不能改。勾上「无焊信」后，已选的行清空，头上焊接费显示 0。编辑最新一条并改了开始年月，保存时服务同时改上一条的结束，用户不在弹框里填上一条的结束。

页面代码与 `generate/`、`list/` 并列，单独一个目录。`list/` 只在操作列加按钮并跳转，不放这一页的模板和逻辑。

```text
static/js/features/bom/welding-process-breakdown/
  generate/       现网拆解页
  list/           现网拆解列表。只加「焊信变更清单」按钮
  change-info/    本页。template.js + index.js
```

`app.js` 的页面加载表增加 `bom-welding-process-change-info`，指向 `change-info/index.js`。与 `generate`、`list` 一样各指各的目录。

| 项 | 值 |
|----|----|
| 列表 | 现网 `menu:bom-welding-process-breakdown-list`，`#/bom-welding-process-breakdown-list` |
| 新页 | `pageMeta` 键 `bom-welding-process-change-info`。面包屑「焊接工程 / 焊接工艺拆解 / 焊信变更」。不写侧栏 `data-page` |
| 前端 | `static/js/features/bom/welding-process-breakdown/change-info/` |
| API | `/api/bom/welding-process-breakdown` |
| 代码 | 页在 `change-info/`。路由在焊接工艺拆解。写入在 `app/services/bom/welding_process_breakdown/`。头是 `bom_welding_process_change_info`，明细是 `bom_welding_process_change_info_lines` |

不另做权限，不新增操作码。能进入拆解列表的人可以打开「焊信变更清单」，并在这一页新增、编辑、删除。编辑和删除只作用于开始最晚的那一条。

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | ``/nodes/{node_id:int}/change-info`` | 这一节点的全部卡片。每条带头，以及按 `line_no` 排列的明细。按开始年月从早到晚。不收 `page`、`size` |
| GET | ``/change-info/unit-price-options`` | 焊接单价选项。查询参数 `node_id`、`year`。只返回该节点基地、该年的 `bom_welding_unit_price`。静态路径，写在 `/{change_id:int}` 之前 |
| POST | ``/nodes/{node_id:int}/change-info`` | 在这一行上新建头和明细。有焊信或无焊信 |
| GET | ``/change-info/{change_id:int}`` | 编辑弹框用的这一条。头加按 `line_no` 排列的明细。不属于当前节点则拒绝 |
| PUT | ``/change-info/{change_id:int}`` | 改头，并整批换上新的明细。不是该节点上开始最晚的一条则拒绝 |
| DELETE | ``/change-info/{change_id:int}`` | 删除这个头。不是该节点上开始最晚的一条则拒绝。明细随 CASCADE 删除。剩下最近一条的结束改为空 |

写入体：`start_year`、`start_month`、`end_year`、`end_month`、`has_weld_info`、`lines`、`remark`。`lines` 的每一项是 `unit_price_id` 和 `qty`。`qty` 是大于 0 的整数。`line_no` 由服务按 `lines` 的顺序从 1 编写，调用方不传。节点取路径上的 `node_id`。无焊信时 `lines` 为空。`amount` 与头上的 `welding_fee` 不由调用方传入。

整数路径写成 `/{node_id:int}`、`/{change_id:int}`。与现网拆解路由放在同一个 `APIRouter` 里。

编辑弹框里的明细列与卡片相同：项目、单位、单价、数量、金额。项目、单位、单价来自选中的焊接单价行，只展示。

## 6. 和设计变更、拆解删除的关系

设计变更种新树时，仍只把旧树 SOP 拆解（主表 + 全部明细）抄到新节点，不抄这两张焊信变更表，也不按新焊信重拆。新号若从某月起要换焊信或标无焊信，在新拆解节点上另记一条。旧节点上的头和明细留在旧节点。

完成停止只让旧树到期，不删这些记录，也不改它们的结束。

保存时，用当时的树根寿命做 §4 的校验。设变稍后把树截短，本表不改已经写下的行。

凡要删掉这个拆解节点——SOP 再生成、批量删除、设变回滚——节点上仍有 `bom_welding_process_change_info` → 拒绝。文案说明先删焊信变更。与「仍被焊接费引用」同一纪律，两句分开，不要合成一句。引用检查里的业务名用「焊信变更」。生成与重拆都不读取、不覆盖这张表，也不改已经落库的拆解明细。

## 7. 给下游

没有审核。下游读已保存的头。保存之后即可读。

一行的含义固定：

| 字段 | 下游可以当作 |
|------|----------------|
| `id` | 溯源 |
| `breakdown_node_id` | 哪一颗拆解节点。记录不跨节点 |
| 开始、结束 | 含首尾。结束空 = 未结束，本行没有代填的失效月 |
| `has_weld_info = true` | 工艺费用头上的 `welding_fee`（已是明细金额之和）。明细给出项目、数量、金额，供核对 |
| `has_weld_info = false` | 这一段没有焊信。明细为空。头上 `welding_fee` 为 0 |

头上的 `welding_fee` 不含 SOP 年账的其它费用。下游若还要加其它费用，自己取年账，不要把别的数写回头上。

本篇不判断某月树还在不在，也不按账期年重乘单价。树后来到期或被截短，行留着。下游若按月取数，自己再问该月这棵树还在不在，再决定用不用这一头。

同一节点上，各条记录彼此不重叠。结束空着的那条，从开始月起往后都算它占着，直到有人改上结束，或新增更晚的一条时由服务写成新开始的前一个月。编辑最新一条的开始后，上一条的结束改成新开始的前一个月。删掉更晚的一条后，剩下最近的一条结束改回空。

抄焊接费见 [抄焊接费](welding-fee-resolve-design.md)。别的下游读这一头和它的明细，不另做第三张变更表。采购对象仍读材料清单焊信原文，不读这两张表。

## 8. 举例

某总成节点在青岛，投产焊信是「凸焊：4；电泳黑漆：0.098m2」。2026 年 7 月起取消电泳。青岛 2026 年焊接单价里有「凸焊」。在该总成节点上加一条，开始年用 2026：

| 头 | 值 |
|----|----|
| 开始 | 2026 年 7 月 |
| 结束 | 空（未结束） |
| `has_weld_info` | 真 |
| `welding_fee` | 这一行的金额 |
| `remark` | 取消电泳 |

| `line_no` | 单价 | 数量 | 金额 |
|-----------|------|------|------|
| 1 | 青岛 2026「凸焊」 | 用户录入，例如 4 | 数量 × 该行单价 |

再留一项，就再选一条同年同基地的单价并录入数量。头上的焊接费改成两行金额之和。单价表里没有的项目不能手写。整段焊信都不要时，`has_weld_info` 为假，明细没有行，`welding_fee` 为 0。

保存之后，节点 `weld_info_raw`、拆解明细、SOP 年账都不变。各月怎么抄这笔焊接费见 [抄焊接费](welding-fee-resolve-design.md)。

2027 年又要电泳：另记一条，从 2027 年 1 月开始，明细改选青岛 2027 的单价。保存时服务把 2026 年 7 月那条的结束写成 2026 年 12 月。数量填整数，例如 4。金额显示到小数点后四位。再把 2027 年这条的开始改到 2027 年 3 月，保存后 2026 年 7 月那条的结束改成 2027 年 2 月。要删 2026 年 7 月那条，须先删 2027 年这条。删掉 2027 年这条后，2026 年 7 月那条的结束改回未结束。

## 9. 做 / 不做

| 做 | 不做 |
|----|------|
| 头 `bom_welding_process_change_info` 加明细 `bom_welding_process_change_info_lines` | 把焊信原文写在头上；改 `bom_welding_process_breakdown_line` |
| 明细从该基地、开始年的焊接单价里选；数量必填；金额和头上焊接费由服务算 | 手写项目或单价；用材料清单焊信原文当明细；保存时调用 Parser；回写节点 `weld_info_raw` |
| 无焊信时头上 `welding_fee` 为 0 | 无焊信仍留着明细金额 |
| 上一条是除本条外开始最晚的那条。新增时补它空着的结束；编辑最新一条的开始时，把它的结束改成新开始的前一个月 | 树被截短时回写结束；新增时改已经写过的结束；编辑不是最新的一条 |
| 只删除该节点上开始最晚的一条。删后把剩下最近一条的结束改为未结束 | 不是最新的一条仍允许删除；删后仍留着被补上的结束 |
| 保存后下游即可读 | 另做审核、反审核 |
| 不另做权限，沿用能进拆解列表的人 | 新增操作码或权限表 |
| 数量为大于 0 的整数；金额四位小数，与单价表一致 | 数量用小数；金额收到三位 |
| 焊信写在哪个节点，记录就挂在哪个节点 | 用下级记录去改总成那一笔 |
| 打开即卡片列表，一张一条，按开始从早到晚。只有一枚「新增」。编辑、删除只在最新一张上 | 表格；单独的查看；更早的卡片放编辑或删除；整页换成录入；用抽屉 |
| 卡片一次列出该节点全部记录，明细直接写在卡片上 | 分页；传 `page`、`size`；点进查看才看明细 |
| 新页放在 `welding-process-breakdown/change-info/`，与 `list/`、`generate/` 并列 | 把这一页的模板或逻辑写进 `list/`；侧栏再开一组「焊信变更」 |
| 设变仍只抄 SOP 拆解 | 设变自动把焊信变更抄到新号 |
