# 焊信变更 — 设计目录

> 状态：**设计定稿，未落地。**
> 对人说 **焊信变更**（与「设计变更」「材料变更」并列）。对象是拆解节点 `bom_welding_process_breakdown_node` 上的焊信（`weld_info_raw`）。与 `bom_welding_process_breakdown_line` 无关。
> 两篇分开写。记录是焊接工艺拆解的辅助表。抄数是焊接费的事。入口在拆解列表每一行的「焊信变更」，打开该节点的新页，不进侧栏，不用抽屉。不另建业务表。
> 设计变更见 [设计变更](../design-change/README.md)。材料变更见 [材料变更](../material-change/README.md)。拆解见 [焊接工艺拆解](../../bom/welding-process-breakdown-design.md)。年账见 [焊接费](../../bom/welding-fee-design.md)。

## 一句话

焊信很少改。节点上的投产焊信、拆解明细、已经算好的 SOP 年账都保持不动。变更是主子表：头 `bom_welding_process_change_info` 记是否有焊信和时间，明细 `bom_welding_process_change_info_lines` 记各句焊信。抄焊接费时带上月份：这个节点有一条已通过的头，并且这个月落在开始与结束之间，就按这张头和它的明细实时算；否则抄 SOP 年账。

常见例子：SOP 焊信里有电泳，过几个月按该基地、该年开始年的焊接单价另选项目并录入数量。头上的焊接费是明细金额之和。若整段焊信都不要了，就标无焊信，头上的焊接费为 0。

## 两篇

| 文档 | 写什么 |
|------|--------|
| [bom_welding_process_change_info](bom-welding-process-change-info-design.md) | 只处理变更：头加明细、写入、审核。从拆解列表进入新页。已通过的头和明细交给下游 |
| [抄焊接费](welding-fee-resolve-design.md) | `resolve_fees`、列表可选月、总成月核价抄到卡上的字段 |

记录篇只处理变更，把已通过的行交给下游。金额在抄费篇。

拆解列表写入这两张表。拆解、焊接费、总成核价不 import 工程变更。总成核价只调焊接费的抄费。
