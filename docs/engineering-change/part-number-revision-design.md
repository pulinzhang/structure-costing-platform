# 工程变更 — 设计说明

> 新切片：投产之后的日常设变。使用方：采购、商务核价。入口 `app/services/engineering_change/`（指挥家 `upload/orchestrator`：prepare → pipeline → persist）。地图见 [README.md](README.md)。  
> **规格就是这一本 Excel**： [t28-2025-07-import-bundle.xlsx](samples/t28-2025-07-import-bundle.xlsx)（生成：[build_t28_2025_07_import_bundles.py](samples/build_t28_2025_07_import_bundles.py) = 运行时 `build_engineering_change_template` = 上传页「下载模板」）。怎么填、写几行、用什么列，打开样表看；本文只写样表上看不见的系统行为。  
> 前提：[有效期](bom-process-die-effective-period-design.md)。关联：[项目](../masterdata/vehicle-model-design.md)、[材料清单 / 采购对象](../bom/bom-procurement-objects-design.md)、[采购价格协议](../costing/procurement-contract-report-design.md)、[冲压工艺确认表](../stamping/stamping-process-confirmation-design.md)、[模具布点](../stamping/stamping-die-management-design.md)、[总成月核价](../costing/assembly-costing-design.md)、[月度引擎](../costing/costing-engine-design.md)。

**规则（样表已经示范的，不再展开）：**

1. 一份 Excel = 一次上传。下载模板即这一本。变更单也可以只有一行。  
2. 第一张表工作表名 **工程变更单**（不要叫封皮）。十列；变更类型只准四句：完成停止 / 改图 / 增加零件 / 此件不装。增加零件 = 加在原来的交货总成上。  
3. 业务表格式 = 对应切片导入模板（列、表头、合并格、填写说明都不另开）。工程变更只多一张 **工程变更单**。解析交给各切片 Parser。BOM / 工艺 / 布点的 Parser、UNIQUE、引擎发现键 **不改**。  
4. 硬门禁：工程变更单 + 材料清单 + 冲压工艺确认表。模具布点（「零件汇总」）**可缺、可空，不拒收**。  
5. **用量不变**：有旧可对的零件用量抄变更前总成；此件不装只能写 0；增加零件按文件用量（须 > 0）。  
6. **旧的到期，不是删掉；新的启用。** BOM 交货总成、冲压工艺确认都是这一套：旧行失效写到生效年月的前一月，行还在；新号/新树另建，从生效月起用。不要说作废。  
7. 工艺新号认材料清单相对旧总成的换号/新加；旧号有仍有效工艺则必须出对应新号。布点不跟时接受 AA 布点与 AB 总成短暂并存，列表可提示。  
8. 种树同一事务自动插本树采购对象 + 本树焊接拆解；改图换号抄工序比例和采购确认。**年度价 / 包装价仍人补**。  
9. 菜单与冲压工程、焊接工程同级。切片独立：只调上游 Service；上游不得 import 本切片。  
10. Excel 进 `upload_files`；变更单行落 `engineering_change_orders`；效果链接供整本回滚。  
11. **号与图（管理）：** 交货总成、分总成必须有内部号；交货总成必须有总成图。图变了就是另一件物料：改图换零件号，禁止改旧号；未来 ERP 出入库也按新零件号办。见第 3 节。

## 1. 四种改法（对着变更单五行读）

格子里是规则。号、名称、层级以样表为准。

| 变更类型 | 变更前总成 | 变更后总成 | 零件层级 | 变更前零件 | 变更后零件 | 材料清单 | 工艺 |
|----------|------------|------------|----------|------------|------------|----------|------|
| 完成停止 | 这个交货总成号 | **空** | 必须 **总成** | **空** | **空** | **不写** 这个总成 | 不加行、**不停**旧工艺 |
| 改图 | 旧交货总成 | 同一号末两位进一位（AA→AB） | 总成 / 一级 / 二级 | 那一层旧号；层级=总成则空 | 那一层新号；层级=总成则空 | 总成列 = 变更后总成；写出**整条链**上换了号的层（改图层 + 到总成之间的上级分总成）。没改的不要抄 | 材料清单里换了号、旧号有工艺的冲压件都要出新号；分总成不出工艺 |
| 此件不装 | 原来那个交货总成 | 同一个总成 AA→AB | 必须 **一级或二级** | 不装的那一层零件号 | **空**（号不变） | 留着该行：用量 0 + 第 23 列含「此件不装」 | 不填这一颗 |
| 增加零件 | 原来那个交货总成 | 同一个总成 AA→AB。禁止把新零件号写成总成 | 必须 **一级或二级** | **空** | 新加的零件号 | 只写新零件（用量 > 0）。没改的不要抄 | 新件看起来是冲压件才必须出这一件新号；标准件 / 胶可省略。**不停**任何旧工艺 |

不是完成停止，交货总成一定换新号。改图是总成里 **已经有的那一颗** 改成 AB；增加零件是 **另外一颗** 加到原来的总成上——「改图、变更前零件空」是漏填，整份拒收。

**改图必须整条链换号。** 变更单只钉改了图的那一层。材料清单把这条链上每一层的新号都写出来：交货总成 → 中间分总成 → 改图层。样表二级改图：`144AB` → `122AB-1` → `122AB`。安装板、吸能盒、标准件没改图，不要抄，导入后从变更前总成带到新总成。

BOM 和冲压工艺确认同一套：**旧的到期，不是删掉；新的启用。** 旧交货总成、旧工艺行用到生效年月的前一月（行还在，按月能看见）；从生效月起用新总成、新工艺行。不是在旧号上改字，也不是删掉旧行。完成停止只有到期、不启用新总成。增加零件：旧总成到期、新总成启用，旧工艺行不到期。工艺只出有工艺的冲压新号（`122AB`）；`122AA-1` 是分总成，不要进工艺表。种树以旧总成为底，按这条链盖新号。

同一总成改图又要去掉某颗：变更单仍写「改图」，不装只写在材料清单里，不要再加一行变更单。

没写在材料清单里的、没改的零件，导入后从变更前总成带到新总成（用量抄旧）。不要把原来总成上所有零件再填一遍。

**此件不装双信号**（两条同时才不写入新总成）：

| 该行 | 系统 |
|------|------|
| 用量数值 = 0 **且** 该行最深一层备注含「此件不装」 | **不写入** 新总成。列表记下这些不装的零件号 |
| 用量 = 0 但备注无「此件不装」 | **整份拒收** |
| 备注有「此件不装」但用量 > 0 或空（空当 1） | **整份拒收** |
| 文件写出用量与变更前总成对应行不同，且不是上表「0 + 此件不装」 | **整份拒收**（工程变更不改用量） |
| 文件里根本没有这行 | **没变**：从变更前总成带走。要标明不装必须留行 |

总成行禁止 0 +「此件不装」（整个总成不再交，用完成停止）。有下级的中间层自身不装时，下级必须仍出现在文件里且全部同样标记。不装之后变更后总成下若没有任何下级零件 → 拒收。用量认 **该层自己的用量列**。投产第一次整表就出现 0 +「此件不装」→ 拒收。

**增加零件**不要和改图、新交货总成混：

| 该份 | 系统 |
|------|------|
| 变更单增加零件、总成两列 AA→AB、变更前零件空、变更后零件有、层级不是总成 | 旧总成到期到前一月、启用新总成，插入新件 |
| 变更单写改图但变更前零件空 | **整份拒收** |
| 增加零件把变更后总成写成新零件号 | **整份拒收** |
| 变更后零件已经装在变更前总成上 | **整份拒收** |
| 变更后零件去掉字母版本后同茎（分总成 `-1` 留在茎上），和旧总成上某一颗相同 | **整份拒收**（这是改图） |
| 变更后零件用量 0 或备注含「此件不装」 | **整份拒收** |
| 新件按现网规则会列入冲压件、该月要走零件价，工艺表却没有该号 | **整份拒收** |
| 新件是标准件/胶，工艺表体空 | 合法 |
| 工艺表出现材料清单没有的新号 | **整份拒收** |

样表不要选 `501007031AA` 做改图：它同时出现在左总成一级和右总成二级，工艺一换成 AB，别处还在用的 AA 也会被停掉。增加零件用新号 `501007040AA`，不要把 `031AA` 写成 `031AB`。

## 3. 号、内部号、图

第一张表叫 **工程变更单**，不要叫封皮。这是设变通知：钉死哪个交货总成、哪种改法、动到哪一层。后面几张才是台账。行落 `engineering_change_orders`，链接用 `change_order_id`。

第二张 `车身件材料清单` 写的是存货结构。管理要求：

| 谁 | 必须有 | 为什么 |
|----|--------|--------|
| 交货总成（含退化供货件） | **内部号** + **总成图**（E 列图示） | 厂内要建档。交什么货，图上是什么。没有内部号进不了 ERP。没有图不收。 |
| 分总成（下面还有下级的一级件） | **内部号** | 能单独采购、能在 ERP 对上号。无内部号会被当成标准件/胶，列不进采购对象。 |
| 标准件 / 胶 / 螺柱等叶子 | 内部号、图都可空 | 不进 ERP 物料码 |

**图变了就是另一件。** 顾客设计图改了，零件号末两位必须进一位（AA→AB）。禁止在旧号上改结构、改图、改字。旧号和新号是两笔存货：核价按月各算各的；未来 ERP 入库、出库、库存按两个物料号办。所以工程变更是「旧的到期、新的启用」，不是改档案。

三套身份不要混：

| 身份 | 认它做什么 | 改图时 |
|------|------------|--------|
| 零件号 | 顾客图号 + 字母版本。工艺、核价、**出入库** 的主键 | 必须换号。不能靠改内部号或只换图、冒充还是同一件。 |
| 内部号 | 厂内 ERP 物料码。给人联查、给未来 ERP 建档。**不是**出入库主键 | 总成 / 分总成不得空。变化行以文件为准；没改的层从旧树抄。同一份清单里一物一码。工厂可以给 AB 仍填原来的内部号（车上同一个供货位置），但收发必须带零件号，才能把 AA 库存和 AB 库存分开。 |
| 总成图 | 这件交货总成长什么样 | 新总成从本张清单抽图落到新节点。缺图拒收。分总成 / 叶子图不强制。 |

导入闸：交货总成、分总成缺内部号拒收；交货总成缺总成图拒收。变化行内部号以文件为准，没改的层从旧树抄；新总成从图落到新节点。同一份清单里一物一码。

## 4. 系统怎么写（样表上看不见的）

有效期针对「一棵对象」，不针对整包头。材料清单写在 **总成树根**；工艺、布点写在 **零件行**。头上 D/00 只标记 SOP。子孙节点落库仍抄树根同一套生失效。采购对象行 **不落** 生失效四列。工程变更 Excel **没有** 采购对象表。

项目下的总成、工艺、布点、采购对象 **默认按年+月过滤**。没选月 = **本月**。禁止走现网「整包覆盖」把未出现在文件里的树、工艺行或布点行删掉。

### 4.1 清单库：按树对齐

青岛 T28 **仍是一份快照**。材料清单交给现网 BOM Parser。设变模式禁止覆盖删库。

| 变更单 / 文件 | 系统做 |
|-------------|--------|
| **完成停止** | 旧交货总成 **到期**到生效年月的前一月（级联子树），行不删。**不启用新树**，不插采购对象/拆解，旧工艺/布点不到期 |
| **改图 / 增加零件 / 此件不装** | 旧总成同样到期（行不删）；**启用**新的一整棵（不在旧节点上改号）。以旧总成为底。**改图整条链换号**：从改图层沿父级走到交货总成，有字母版本的中间分总成一律进一位（`122AA-1`→`122AB-1`），与材料清单上级新号对齐；没改的零件原号带走，用量抄旧。文件里的变化行盖上去。用量 0 且备注含「此件不装」的行 **不插入**。增加零件插入变更后那一颗，用量按文件。**序号继承旧总成投产序号**。新总成生效=生效年月；失效抄项目结束月。节点 `bom_version` 写 **本张材料清单表头版本**；snapshot 头仍 SOP 字 |
| 未改总成 | **跳过** |
| 文件没有、库里仍有效 | **不动**。唯一例外是完成停止点名的那一棵 |
| 新交货总成已在库里 | **整单拒绝** |

禁止：把这份 Excel 当成新 `bom_version` 快照整表覆盖；在旧总成节点上改零件号；走 `BomService.create_node`（走 `BomNodeWrite`）。内部号 / 总成图见第 3 节：总成、分总成不得空号；总成必须有图；变化行内部号以文件为准，没改的层从旧树抄。简图从本张清单抽到新节点，目录仍挂 snapshot 头版本（D/00）。

SOP 再导：只更新 **生效月 = 项目 SOP 开始月** 且仍有效的树。已失效的、以及生效月是工程变更切点的 **整棵跳过**。

校验（失败则整份拒收）：

- 变更单至少一行；每一行项目、生效年月与上传页一致；多行时项目/生效年月必须相同。  
- 四种类型的十列符合第 1 节。同一本里变更前总成、变更后总成不得重复。  
- 变更前总成仍有效。一级/二级改图、此件不装：变更前零件必须装在这个总成上，层级一致。增加零件：变更后零件不得已经装在这个总成上。  
- 非完成停止：变更后总成 = 变更前总成字母版本进一位 = 材料清单该行新总成。整本：材料清单全部 L0 = 非完成停止变更单行的变更后总成集合。字母版本在分总成号里在 `-1` 前面（`122AA-1`→`122AB-1`），不要按字符串末两位切。  
- 改图且零件层级=一级/二级：变更单变更后零件必须出现在材料清单对应层级。材料清单还须写出这条链上每个中间分总成的新号（如 `122AA-1`→`122AB-1`）。种树按整条链盖号，没改的零件不换。  
- 材料清单第 1 列若填了序号，必须等于该总成投产序号。  
- 该基地+项目只有一份投产清单头；上传页项目 = 变更单项目 = 材料清单项目代号；材料清单顾客名称 = 该投产清单头顾客。  
- 生效年月晚于旧总成生效月，且不晚于项目结束月。项目在 **生效年月** 可引入。  
- 交货总成、分总成内部号不得空；交货总成必须有总成图。变化行内部号以文件为准。同一份清单里一物一码。材料清单顾客 / 项目空不得跳过互校。  
- 此件不装：变更单钉的零件必须出现在材料清单且用量 0 + 备注含「此件不装」；中间层不装时下级必须同样标记。变更单一行不够。  
- 增加零件：变更后零件不得已装在变更前总成上，也不得与树上已有件同字母版本茎（那是改图）。新件备注禁止「此件不装」。

### 4.2 冲压库：按零件号对齐

格式就是冲压工艺切片确认表，同一 Parser。有效期写在零件行。此件不装、完成停止不填零件行 → **不加新行、旧号不到期**。设变 **不得**调用 SOP `save_parts` 拒新号路径。

| 文件里的零件号 | 系统做 |
|----------------|--------|
| 新号 | **先**让同厂同项目下字母版本同茎、仍有效的旧号 **到期**到生效年月的前一月（行不删，有则继承 `seq_no`）；**再启用新行**。茎 = 去掉两位字母版本，分总成 `-1` 留在茎上（`122AA` 与 `122AA-1` 不是同一个号）。版本=本张工艺确认表表头。**改图换号：零件信息除零件号、版本、生失效外整行抄旧号，工序整表相同**（确认表只用来出新号/门禁，不重写材料、尺寸、工序）。无旧号可对 → 全新号，按确认表新插，`seq_no = max+1` |
| 已有号 | **一律跳过** |
| 表体空 | **不插、不到期** |
| 文件没有的旧号 | **不删、不到期**。只有文件里出现对应新号时才让旧号到期 |

`cost_ratio`：改图换号整表抄旧工序，比例一起带走。增加零件 / 无旧号可对 → 确认表解析默认。Excel 没有这一列。

字母版本到期是 **按号、全项目同厂**，只在变更单 **改图** 时做（写失效月，不删行）。旧号若还挂在另一棵仍有效、本文件又不替换的树上 → **整份拒收**。增加零件 **禁止**按字母版本让旧号到期。

工艺表允许出现的新冲压号，认 **本文件材料清单相对旧总成换号或新加的号**（零件层级=总成时变更单变更后零件是空的）：

| 变更单 | 工艺表 |
|------|--------|
| 改图 | 材料清单里每个换了号、且旧号在该厂有仍有效工艺的冲压件，都必须有新号 |
| 增加零件 | 新件按材料清单判断是冲压件时 **必须**含变更后零件；标准件 / 胶可省略。**禁止**字母版本让旧号到期 |
| 完成停止 / 此件不装 | 表体空 → **不加新行、旧号不到期** |

工艺表出现材料清单里没有的新号 → 拒收。材料清单换了号、旧号有仍有效工艺、工艺表却没有新号 → 拒收。旧号本来就没有工艺行 → 不必出。

### 4.3 模具布点：有就写，没有就不挡

**不是硬门禁。** 没有「零件汇总」、表体空，都不拒收、不碰已有布点。设变 **不得**调用 SOP `upload_service`（空表体会报「未解析到零件数据」）。

写出新号才按号增行（改图换号时 `alloc_ratio` 从旧号同工序抄；增加零件禁止按字母版本让旧号到期）。已有号跳过。变更单是改图、旧号已有布点、文件没写出新号 → **不拒收、旧布点不动**；列表可提示「材料清单有换号、布点未跟」。旧号还装在别的仍有效总成上、文件却要按字母版本让它到期 → 仍拒收。

检具费另表、同样不是硬门禁（本期不展开公式）。

### 4.4 采购对象：设变导入后自动带出

**导入后不必再点「开始生成」。** 种树成功后，同一事务按现网分类规则扫新树插行。对象行不加生失效四列；命中只用树根 as_of。细则见 [bom-procurement-objects-design.md](../bom/bom-procurement-objects-design.md) §14。

该 snapshot 一旦有工程变更写入的树，采购对象 / 拆解「开始生成」拒绝（门禁之 2）。缺对象只能工程变更重传。

尚无采购对象清单头则先建空头再插行。匹配只认被替换的那一棵旧树：

| 新树上的节点 | 系统做 |
|--------------|--------|
| 列入采购对象，旧树有同行（同 `part_number` + `section` + `object_kind`） | 插新行；确认三态 / 确认人时 / 确认备注 / `supplier_name` **从旧树抄**。不抄 `audit_status` |
| 列入采购对象，能对上旧树字母版本换号，且 `object_kind` 不变 | 同上，从旧号同行抄。改图整条链上的分总成 AA→AB、此件不装时上级分总成换号，同样适用 |
| 列入采购对象，无同行且无字母版本可对（增加零件新号） | 插新行，待确认、厂家空 |
| 核对区 | 插新行；无确认可抄。用量 0 +「此件不装」未插入的叶子不插 |
| 完成停止 | 不插 |
| 旧树已有行 | 不动 |

`object_kind` 变了当新号，不抄确认。抄来的厂家不跑 `require_enabled`。

#### 4.4.1 焊接拆解：只拆新树

**不得**调用现网整包 `POST /generate`。只扫新种那一棵有 `weld_info` 的节点插行。拆解 / 焊接费行的 `bom_version` **抄 snapshot 头 D/00**，不要抄节点变更字。完成停止不插拆解。门禁之 2、之 3 见 §4.6。细则见 [welding-process-breakdown-design.md](../bom/welding-process-breakdown-design.md)。

### 4.5 价表与核算

工程变更不抄年度价 / 包装价。换了号的采购对象人补；没改号的不必出新价行。不装的零件不进该月核价。

引擎：该月只收有效树根（按 SOP `seq_no` 序）；叶子冲压价抄该月有效工艺行。总成卡抄树根项目号、**节点**版本字；发现范围仍按 snapshot 头版本。完成停止不停工艺行：零件价月账仍可能算到旧总成下的冲压号；总成核价不收已失效的树。

### 4.6 与投产切片怎么协作

BOM / 工艺 / 布点的 Parser、UNIQUE、引擎发现键、`create_node`、投产空表硬停：**都不改**。工程变更抽表后自己写入，不走投产三条覆盖链。

| 现网 Parser / UNIQUE | 本切片 |
|----------|------------|
| BOM Parser 只读第一张表 | 按表名抽出 `车身件材料清单` 再交给 Parser |
| 工艺 Parser 自动找「零件号+工序」或退回第一张 | 按表名抽出 `冲压工艺确认表` |
| 布点 `find_sheet` 扫到「零件号」就用 | 有「零件汇总」才按表名抽出。**禁止**对整本文件调用 `parse_die_layout_excel`。没有这张表 = 跳过，不拒收 |
| `bom/upload` 用 Excel 头版本对 snapshot | 本切片不走这条。按基地+项目找 **唯一** 投产清单头，头仍 D/00 |
| `create_node` 强制节点版本=头 | 走 `BomNodeWrite` |
| 布点 SOP 空表体硬停 | 没有「零件汇总」、或抽出后零行 = 跳过，不调用 `die/upload_service` |
| 工艺 SOP 拒新号 | 本切片自己按号增行；已有号跳过 |
| 引擎 `L0Scope` / 拆解 UNIQUE 用 snapshot 头 | 拆解与焊接费行 `bom_version` 抄头 |
| 宪法同步 Excel 封闭名单 | 工程变更是长任务（`task_id`），不进该名单 |

| 门禁 | 改哪个入口 | 判定 |
|------|------------|------|
| 1 | `bom/upload/persist/nodes.py` 再导对齐树 | 只更新：树根仍有效 **且** 生效月 = 项目 SOP 开始月。已失效、或生效月是工程变更切点的整棵 **跳过** |
| 2 | 采购对象 / 焊接拆解「开始生成」 | 该 snapshot 存在已失效树根，**或** 存在生效月 ≠ 项目 SOP 开始月的树根 → 409 |
| 3 | 引擎 `annual_welding_breakdown` | 年交集已齐 → 跳过；缺新树拆解 → **禁止**调现网整包 `generate` |

写入顺序（一次事务，失败全滚）：

```text
变更单 + 材料清单 + 工艺硬门禁校验（布点缺表/空表不拒收）
  → 按表名抽业务表（缺工程变更单 / 材料清单 / 工艺确认表整单失败）
  → 按变更单行顺序、一次事务：
     完成停止：旧交货总成到期（不删行）
     改图 / 增加零件 / 此件不装：旧交货总成到期 + 启用新树
  → 每棵新树：本树采购对象插行、本树焊接拆解插行
  → 工艺表按号增行一次（仅改图行才让旧号到期；不删行）
  → 布点：有零件行才按号增行；没有这张表或表体空则跳过
  → 写变更单行 + 效果链接 → 回写上传头 success
```

三库都禁止整包删。AB→AC 同一套。

## 8. 产品：上传与列表

单独做，不塞进投产三页。此件不装、增加零件都在同一本 Excel 里，不另开按钮。

### 8.1 上传

| 字段 | 与 Excel 怎么校 |
|------|----------------|
| 基地 | 找到该基地+项目的唯一投产清单。变更单无此列 |
| 项目 | 必须 = 变更单「项目」= 材料清单「项目代号」= 该投产清单项目 |
| 年度 + 月份 | 必须 = 变更单「生效年月」 |
| 文件 | `.xlsx`；即样表这一本的形态 |

顾客从材料清单表头读。版本从各表页表头读，不要合成一个「上传版本」字段。

同基地+项目允许排队多个任务；本本任一变更后总成已被成功写入或进行中的任务占用 → 409。失败任务不占号。文件一入队即 `file_trace.register_existing`（失败校验也留档）。上传走后台任务。

`GET /api/engineering-change/template` 即样表这一本，文件名 `工程变更导入模板.xlsx`。模板下载不写 `upload_files`。

### 8.2 列表与详情

分页。**列表以变更单行为粒度**（一本 Excel 成功后 N 行，同一 `upload_log_id`）。列对齐样表工程变更单十列：项目、生效年月、变更前/后总成、总成名称、变更类型、零件层级、变更前/后零件、零件名称；另加材料清单序号、基地、上传人、源文件、整本状态。

点行看详情：变更单十列 + `excel_row` + 效果链接（`upload_log_id` / `change_order_id` / 前后实体 id）+ 失败 `message`。操作：**删除 = 回滚**。删列表任意一条变更单行，都按 `upload_log_id` 把本次上传全部回滚，并 **物理删除** 上传头 / 变更单行 / 效果链接，列表不再留「已回滚」。原件下载走文件溯源，存档 Excel **保留**。

### 8.3 三张表

全新切片：现网历史表直接 DROP，不迁数据。

一次尝试一行上传头 `engineering_change_upload_logs`（`pending` / `success` / `failed`）。成功后按变更单行插入 `engineering_change_orders`（1 上传头 : N 变更单行；十列 + `excel_row` + 变更单实体 `id`）。`engineering_change_effect_links` 存 `upload_log_id`、`change_order_id` 与前后实体 id：`assembly_l0` / `process_part` / `die_part` / `procurement_object` / `welding_breakdown` / `procurement_list`。缺链接 = 不可回滚，禁止标成功。

删除本次变更：上传头 `success`（失败记录可直接物理删除，进行中禁止删）；本本全部变更单 `active`；其后没有以本本任一 `after_assembly` 为变更前总成的未删除记录。按效果链接逆序恢复业务对象，同一事务里 **物理删除** 本本三张表。存档 Excel **保留**。已审采购对象须先反审。不留 `rolled_back` 行。

### 8.4 API

前缀 `/api/engineering-change`。JSON 一律 `ApiResponse[T]`；分页 `page` + `size`。异步上传 HTTP **200** + `AsyncTaskAcceptedVO`。

| 方法 | 路径 | 权限 | 出参 |
|------|------|------|------|
| GET | `/template` | `ENGINEERING_CHANGE_UPLOAD_UPLOAD` | 样表文件流 |
| POST | `/upload` | 同上 | `AsyncTaskAcceptedVO`（multipart：基地/项目/年/月/file） |
| GET | `/upload/tasks/{task_id}` | view / upload / order-list view 任一 | `AsyncTaskProgressVO` |
| GET | `/change-orders` | `ENGINEERING_CHANGE_ORDER_LIST_VIEW` | `PageResult[EngineeringChangeListRowVO]`（变更单行；`upload_log_id` 整本删除） |
| GET | `/change-orders/{upload_log_id}` | 同上 | 头 + 变更单行 + 效果链接 |
| DELETE | `/change-orders/{upload_log_id}` | `ENGINEERING_CHANGE_ORDER_LIST_DELETE` | 整本回滚后物理删除本记录 |

步长建议：10 校验变更单与抽表 → 40 种树/失效 → 70 对象+拆解 → 90 工艺+布点 → 100 回写日志。失败：业务事务全滚，不留半套新树。

### 8.6 权限

不要绑投产三页。一级分组 `menu:engineering-change`，与 `menu:stamping` / `menu:bom` 同级。组内上传 / 工程变更单列表。`defaults` / `mandatory` 不加入。按 [permission-design §0](../permission-design.md) 九步一次做齐。

| code | 用途 |
|------|------|
| `menu:engineering-change` | 一级分组 |
| `menu:engineering-change-upload` + `op:…:view` / `op:…:upload` | 上传页；下模板、POST 上传 |
| `menu:engineering-change-order-list` + `op:…:view` / `op:…:delete` | 工程变更单列表 / 详情；删除回滚。原件走文件溯源 |

## 9. 拒收原因

用 `BusinessException(message=..., code=400|409)`；常量名放 `app/common/engineering_change_gates.py`。对人只展示 `message`。

| 常量名 | HTTP | 要旨 |
|--------|------|------|
| `EC_CHANGE_ORDER_ROW_COUNT` | 400 | 工程变更单至少一行 |
| `EC_CHANGE_ORDER_TYPE_INVALID` | 400 | 变更类型只准四句 |
| `EC_CHANGE_ORDER_COLUMNS` | 400 | 工程变更单十列填法不符合该变更类型 |
| `EC_EFFECTIVE_MISMATCH` | 400 | 生效年月与上传页年+月不一致 |
| `EC_PROJECT_MISMATCH` | 400 | 工程变更单项目 / 材料清单项目代号与上传页不一致 |
| `EC_CUSTOMER_MISMATCH` | 400 | 材料清单顾客名称与投产清单头不一致 |
| `EC_BEFORE_ASSEMBLY_INVALID` | 400 | 变更前总成无效或不存在/已失效 |
| `EC_AFTER_ASSEMBLY_EXISTS` | 409 | 变更后总成已存在 |
| `EC_AFTER_ASSEMBLY_BUSY` | 409 | 同一变更后总成正在导入 |
| `EC_SEQ_MISMATCH` | 400 | 材料清单序号与投产序号不符 |
| `EC_BOM_NEW_ROOT` | 400 | 材料清单新总成数量或号与工程变更单不符 |
| `EC_QTY_CHANGED` | 400 | 用量与变更前总成不一致（工程变更不改用量） |
| `EC_NOT_INSTALL_SIGNAL` | 400 | 此件不装必须用量 0 且备注含「此件不装」 |
| `EC_ADD_VS_REVISE` | 400 | 改图变更前零件空，或增加零件把新号写成总成 / 与树上已有件同茎 |
| `EC_INTERNAL_REQUIRED` | 400 | 交货总成、分总成必须有内部号 |
| `EC_ASSEMBLY_SKETCH_REQUIRED` | 400 | 交货总成必须有总成图 |
| `EC_PART_NOT_ON_TREE` | 400 | 变更前零件不在该交货总成上，或层级不一致 |
| `EC_REVISE_FILE_CHAIN` | 400 | 改图必须在材料清单写出变更后零件及中间分总成新号 |
| `EC_NOT_INSTALL_CHILDREN` | 400 | 中间层此件不装时，下级必须同样标记 |
| `EC_ADD_ALREADY_ON_TREE` | 400 | 增加零件不得已装在变更前总成上 |
| `EC_PROCESS_MISSING_NEW` | 400 | 材料清单换号/新加且旧号有工艺，工艺表缺对应新号 |
