# 工程变更 — 设计说明

> 新切片：投产之后的日常设变。使用方：采购、商务核价。入口 `app/services/engineering_change/`（指挥家 `upload/orchestrator`：prepare → pipeline → persist）。地图见 [README.md](README.md)。  
> **规格就是这一本 Excel**： [t28-2025-07-import-bundle.xlsx](samples/t28-2025-07-import-bundle.xlsx)（生成：[build_t28_2025_07_import_bundles.py](samples/build_t28_2025_07_import_bundles.py) = 运行时 `build_engineering_change_template` = 上传页「下载模板」）。怎么填、写几行、用什么列，打开样表看；本文只写样表上看不见的系统行为。  
> 前提：[有效期](bom-process-die-effective-period-design.md)。关联：[项目](../masterdata/vehicle-model-design.md)、[材料清单 / 采购对象](../bom/bom-procurement-objects-design.md)、[采购价格协议](../costing/procurement-contract-report-design.md)、[冲压工艺确认表](../stamping/stamping-process-confirmation-design.md)、[模具布点](../stamping/stamping-die-management-design.md)、[总成月核价](../costing/assembly-costing-design.md)、[月度引擎](../costing/costing-engine-design.md)。

**规则（样表已经示范的，不再展开）：**

1. 一份 Excel = 一次上传。下载模板即这一本。变更单也可以只有一行。  
2. 第一张表工作表名 **工程变更单**（不要叫封皮）。十列；变更类型只准四句：完成停止 / 改图 / 增加零件 / 此件不装。增加零件 = 加在原来的交货总成上。**改图按零件层级拆成总成 / 一级 / 二级**，加上此件不装、增加零件，一个交货总成上共 **五种会改图的场景**（见第 1 节）。只要发生其中一种：总成图必然变了，交货总成零件号必然换。  
3. 业务表格式 = 对应切片导入模板（列、表头、合并格、填写说明都不另开）。工程变更只多 **工程变更单** 和 **工程变更填写说明**。解析交给各切片 Parser。工程变更 **不解析** 模具布点。BOM / 工艺 / 布点的 Parser、UNIQUE、引擎发现键 **不改**。  
4. 硬门禁：工程变更单 + 材料清单 + 冲压工艺确认表。工程变更 **不要**「零件汇总」：模具布点 **逻辑建立**（改图有旧布点则从库里整行抄到新号，含分摊比例），不读 Excel。新号布点简图从 **冲压工艺确认表** 该号零件简图抄过去。一本一个项目号（上传页、变更单、材料清单拆出的项目代号、确认表拆出的项目号必须同一）。两张表头版本必须同一字。变更生效月必须在项目有效期内。上传前该投产 snapshot **必须已有 SOP 生成过的采购对象清单头**（含只做完成停止）；系统不代建空头。  
5. **用量：** 本树没有「增加零件」时，有旧可对的零件用量必须等于变更前总成（此件不装只能写 0），否则 `EC_QTY_CHANGED`。本树只要有「增加零件」，已经是新总成，不再拿旧树用量拒收；带走的件默认仍抄旧用量，文件另写了且该号未换号则用文件用量。增加零件本身按文件用量（须 > 0）。  
6. **旧的到期，不是删掉；新的启用。** BOM 交货总成、冲压工艺确认、模具布点都是这一套：旧行失效写到生效年月的前一月，行还在；新号/新树另建，从生效月起用。不要说作废。  
7. **新旧号只认工程变更单写出的字，禁止猜下一位字母（不要自己把 AA 加成 AB、把 AB 加成 AC）。** 变更前总成 / 变更后总成 / 变更前零件 / 变更后零件以该行十列为准。材料清单总成列必须等于该行变更后总成；改图层号必须等于该行变更后零件。中间分总成新号只认材料清单已经写出的号，也不要自己进一位。  
8. 工艺新号认变更单 + 材料清单已经写出的换号/新加；旧号有仍有效工艺则必须出对应新号。布点不填表、不抽表：改图且变更前零件有旧布点则 **逻辑建立** 新号布点（从库抄旧）；没有旧布点就不建。简图只从工艺确认表出，再抄到新号布点。  
9. 种树同一事务自动插本树采购对象 + 本树焊接拆解（拆解从旧树已有结果抄，禁止按焊信重拆）；改图换号抄工艺工序比例、布点分摊比例和采购确认。种新树时抄包装运输费（旧交货总成→新交货总成）和年度零件价（种树 remap 里换了号的零件）；无旧行则跳过。增加零件的新号无旧年度价可对，仍人补。  
10. 菜单与冲压工程、焊接工程同级。切片独立：只调上游 Service；上游不得 import 本切片。  
11. Excel 进 `upload_files`；变更单行落 `engineering_change_orders`；效果链接供整本回滚。  
12. **号与图（管理）：** 交货总成、分总成必须有内部号；交货总成必须有总成图。图变了就是另一件物料：换零件号，禁止改旧号；未来 ERP 出入库也按新零件号办。见第 3 节。新号写在变更单上，系统照抄，不推算末两位。  
    **硬约束：** 一个交货总成只要碰上第 1 节五种场景之一（总成改图 / 一级改图 / 二级改图 / 此件不装 / 增加零件），总成图就变了，**变更后总成必须写出新零件号**，且不得等于变更前总成。完成停止不是这五种：没有新图、没有新号。禁止在旧总成号上改结构、少装、加装。

## 1. 一个总成上的五种场景（对着变更单读）

变更类型格子仍只准 **四句**（完成停止 / 改图 / 增加零件 / 此件不装）。对人说总成 / 一级 / 二级，不要说 L0/L1/L2。

**硬约束（先于下面各行填法）：** 一个交货总成只要发生下列五种之一，顾客这张 **总成图必然变了**，交货总成就是另一件物料，**零件号必然换**。变更后总成必须写出新号（写成 AB 用 AB，写成 AC 用 AC，系统不推算）；材料清单总成列必须等于这个新号。五种可以同时发生在同一总成上（连续行、前后总成格子上下合并），前后总成号各只出现一次。

| 场景 | 变更类型格子 | 零件层级 | 为什么总成图变了 | 交货总成零件号 |
|------|--------------|----------|------------------|----------------|
| 总成改图 | 改图 | **总成** | 总成自己的图改了 | **必换**（变更后总成；变更前/后零件空） |
| 一级改图 | 改图 | **一级** | 总成里那颗一级件换图，总成图跟着变 | **必换** |
| 二级改图 | 改图 | **二级** | 总成里那颗二级件换图，总成图跟着变 | **必换** |
| 此件不装 | 此件不装 | **一级或二级** | 总成少装了一颗，交的货长什么样变了 | **必换**（不装那一层号不变；变的是总成号） |
| 增加零件 | 增加零件 | **一级或二级** | 总成多装了一颗，交的货长什么样变了 | **必换**（禁止把新零件号写成总成） |

**完成停止不是这五种。** 整个交货总成不再交：没有新图、不启用新总成、变更后总成空。不要用「总成行 0 + 此件不装」冒充。

格子里是规则。号、名称、层级以样表为准。样表五行示范了完成停止和后四种场景（未示范总成改图，规则仍生效）。

| 变更类型 | 变更前总成 | 变更后总成 | 零件层级 | 变更前零件 | 变更后零件 | 材料清单 | 工艺 |
|----------|------------|------------|----------|------------|------------|----------|------|
| 完成停止 | 这个交货总成号 | **空** | 必须 **总成** | **空** | **空** | **不写** 这个总成 | 不加行、**不停**旧工艺 |
| 改图 | 旧交货总成 | **变更单写出的新总成号**（样表是 AB；写成 AC 就用 AC，系统不推算） | 总成 / 一级 / 二级 | 那一层旧号；层级=总成则空 | 那一层新号；层级=总成则空 | 总成列 = 变更后总成；写出**整条链**上换了号的层（改图层 + 到总成之间的上级分总成，号以表为准）。没改的不要抄 | **只一级/二级改图**才进工艺/布点换号表。层级=总成：只换总成号、种新树，交货总成不是冲压工艺行，不进换号表。一级/二级：材料清单里换了号、旧号有工艺的冲压件都要出新号；分总成不出工艺。布点不填表：变更前零件有旧布点则逻辑建立新号布点（整行抄旧，含分摊比例）；简图从本张工艺确认表抄到新号布点 |
| 此件不装 | 原来那个交货总成 | **变更单写出的新总成号** | 必须 **一级或二级** | 不装的那一层零件号 | **空**（号不变） | 留着该行：用量 0 + 第 23 列含「此件不装」 | 不填这一颗 |
| 增加零件 | 原来那个交货总成 | **变更单写出的新总成号**。禁止把新零件号写成总成 | 必须 **一级或二级** | **空** | 新加的零件号 | 只写新零件（用量 > 0）。没改的不要抄 | 新件看起来是冲压件才必须出这一件新号；标准件 / 胶可省略。**不停**任何旧工艺。无旧布点可对则 **不建** 布点 |

五种场景：交货总成一定换新号，号以变更单为准，**不得等于变更前总成**。改图是总成里 **已经有的那一颗** 换成变更后零件；增加零件是 **另外一颗** 加到原来的总成上——「改图、变更前零件空」是漏填，整份拒收。此件不装 / 增加零件同样要换总成号：不是「结构变了但总成号还用旧的」。

**改图必须整条链换号，号都来自文件。** 变更单只钉改了图的那一层（变更前零件 → 变更后零件）。材料清单把这条链上每一层的新号都写出来：交货总成（= 变更后总成）→ 中间分总成（表上写什么用什么）→ 改图层（= 变更后零件）。样表二级改图：`144AB` → `122AB-1` → `122AB`。系统 **不得**把未写在变更单、也未写在材料清单上的层自己进一位。安装板、吸能盒、标准件没改图，不要抄，导入后从变更前总成带到新总成。

BOM、冲压工艺确认、模具布点同一套：**旧的到期，不是删掉；新的启用。** 旧交货总成、旧工艺行、旧布点行用到生效年月的前一月（行还在，按月能看见）；从生效月起用新总成、新工艺行、新布点行。不是在旧号上改字，也不是删掉旧行。完成停止只有到期、不启用新总成，旧工艺/布点不到期。增加零件：旧总成到期、新总成启用，旧工艺/布点不到期。工艺只出有工艺的冲压新号（变更后零件；样表 `122AB`）；分总成不要进工艺表。种树以旧总成为底，按变更单和材料清单写出的号盖上去。改图还用原来那副模（改模）：布点不填表，按变更单从变更前零件 **逻辑建立** 新号布点；简图从工艺确认表抄过去。

同一总成碰上五种里的好几处：变更前总成、变更后总成各只出现一次，连续行并把格子**上下合并**。完成停止不用填变更后总成。

没写在材料清单里的、没改的零件，导入后从变更前总成带到新总成（用量抄旧）。不要把原来总成上所有零件再填一遍。本树含「增加零件」时不拿旧用量拒收（已经是新总成）。

**此件不装双信号**（两条同时才不写入新总成）：

| 该行 | 系统 |
|------|------|
| 用量数值 = 0 **且** 该行最深一层备注含「此件不装」 | **不写入** 新总成。列表记下这些不装的零件号 |
| 用量 = 0 但备注无「此件不装」 | **整份拒收** |
| 备注有「此件不装」但用量 > 0 或空（空当 1） | **整份拒收** |
| 文件写出用量与变更前总成对应行不同，且不是上表「0 + 此件不装」 | **本树没有增加零件 → 整份拒收**（不改用量）。本树有增加零件 → **不拒**，已是新总成 |
| 文件里根本没有这行 | **没变**：从变更前总成带走。要标明不装必须留行 |

总成行禁止 0 +「此件不装」（整个总成不再交，用完成停止）。有下级的中间层自身不装时，下级必须仍出现在文件里且全部同样标记。不装之后变更后总成下若没有任何下级零件 → 拒收。用量认 **该层自己的用量列**。投产第一次整表就出现 0 +「此件不装」→ 拒收。

**增加零件**不要和改图、新交货总成混：

| 该份 | 系统 |
|------|------|
| 变更单增加零件、总成两列写出前后总成、变更前零件空、变更后零件有、层级不是总成 | 旧总成到期到前一月、启用新总成，插入新件 |
| 变更单写改图但变更前零件空 | **整份拒收** |
| 增加零件把变更后总成写成新零件号 | **整份拒收** |
| 变更后零件已经装在变更前总成上（整号相同） | **整份拒收** |
| 变更后零件用量 0 或备注含「此件不装」 | **整份拒收** |
| 新件按现网规则会列入冲压件、该月要走零件价，工艺表却没有该号 | **整份拒收** |
| 新件是标准件/胶，工艺表体空 | 合法 |
| 工艺表出现材料清单没有的新号 | **整份拒收** |

样表不要选 `501007031AA` 做改图：它同时出现在左总成一级和右总成二级，工艺一换成新号，别处还在用的旧号也会被停掉。增加零件用新号 `501007040AA`，不要把 `031AA` 改写成另一个版本号再当成增加零件。

## 3. 号、内部号、图

第一张表叫 **工程变更单**，不要叫封皮。这是设变通知：钉死哪个交货总成、哪种改法、动到哪一层。后面几张才是台账。行落 `engineering_change_orders`，链接用 `change_order_id`。

第二张 `车身件材料清单` 写的是存货结构。管理要求：

| 谁 | 必须有 | 为什么 |
|----|--------|--------|
| 交货总成（含退化供货件） | **内部号** + **总成图**（E 列图示） | 厂内要建档。交什么货，图上是什么。没有内部号进不了 ERP。没有图不收。同一总成合并多行只需一张总成图，不逐行检验。 |
| 分总成（下面还有下级的一级件） | **内部号** | 能单独采购、能在 ERP 对上号。无内部号会被当成标准件/胶，列不进采购对象。单件图示归二级，本层不强制。 |
| 一级叶子 / 二级零件 | **单件图示**（P 列，或从冲压工艺确认表抄） | 材料清单写出的一级叶子、二级必须有图。清单缺图时按零件号从工艺确认表抄到 BOM sketches 目录。两列都空才拒收。此件不装不要求。 |

**图变了就是另一件。** 第 1 节五种场景只要发生一种，这件交货总成的总成图就变了，必须换 **交货总成零件号**（写在变更后总成）。一级 / 二级改图还要换那一层零件号；此件不装不换那一层号，但总成号仍要换；增加零件是新加一颗，总成号仍要换。禁止在旧总成号上改结构、改图、改字、少装、加装。旧号和新号是两笔存货：核价按月各算各的；未来 ERP 入库、出库、库存按两个物料号办。所以工程变更是「旧的到期、新的启用」，不是改档案。新号是 AB 还是 AC，以变更单为准，系统不推算。

三套身份不要混：

| 身份 | 认它做什么 | 改图时 |
|------|------------|--------|
| 零件号 | 顾客图号 + 字母版本。工艺、核价、**出入库** 的主键 | 必须换号，号写在变更单上。不能靠改内部号或只换图、冒充还是同一件。系统不猜下一位字母。 |
| 内部号 | 厂内 ERP 物料码。给人联查、给未来 ERP 建档。**不是**出入库主键 | 总成 / 分总成不得空。变化行以文件为准；没改的层从旧树抄。同一份清单里一物一码。工厂可以给新号仍填原来的内部号（车上同一个供货位置），但收发必须带零件号，才能把旧号库存和新号库存分开。 |
| 总成图 | 这件交货总成长什么样 | 新总成从本张清单「总成图示」抽图。同一总成合并多行只需一张。缺图拒收。 |
| 单件图示 | 一级叶子 / 二级长什么样 | 材料清单 P 列优先；缺则按零件号从冲压工艺确认表抄到 BOM sketches 目录。两处都没有拒收。分总成本层不强制。 |

导入闸：交货总成、分总成缺内部号拒收；交货总成缺总成图拒收（合并总成一张即可）；材料清单写出的一级叶子 / 二级缺单件图示拒收（可从工艺确认表抄）。变化行内部号以文件为准，没改的层从旧树抄；新总成从图落到新节点。同一份清单里一物一码。

## 4. 系统怎么写（样表上看不见的）

有效期针对「一棵对象」，不针对整包头。材料清单写在 **总成树根**；工艺、布点写在 **零件行**。头上 D/00 只标记 SOP。子孙节点落库仍抄树根同一套生失效。采购对象行 **不落** 生失效四列（列表 join 树根展示；与拆解同一纪律）。工程变更 Excel **没有** 采购对象表。

项目下的总成、工艺、布点 **默认按年+月过滤**（没选月 = **本月**）。采购对象**列表**默认包含已过期、不按年+月裁，见 [采购对象 §14](../bom/bom-procurement-objects-design.md)。核价 / 签约 / 引擎仍按账期月命中。禁止走现网「整包覆盖」把未出现在文件里的树、工艺行或布点行删掉。

### 4.1 清单库：按树对齐

青岛 T28 **仍是一份快照**。材料清单交给现网 BOM Parser。设变模式禁止覆盖删库。

| 变更单 / 文件 | 系统做 |
|-------------|--------|
| **完成停止** | 旧交货总成 **到期**到生效年月的前一月（级联子树），行不删。**不启用新树**，不插采购对象/拆解，旧工艺/布点不到期 |
| **改图 / 增加零件 / 此件不装** | 旧总成同样到期（行不删）；**启用**新的一整棵（不在旧节点上改号）。以旧总成为底。**改图整条链换号**：变更单钉的那一层用变更前零件 → 变更后零件；材料清单写出的中间分总成新号按文件盖上。**禁止**对未写出的层按字母版本自己进一位。没改的零件原号带走，用量抄旧。本树有「增加零件」时不拿旧用量拒收。文件里的变化行盖上去。用量 0 且备注含「此件不装」的行 **不插入**。增加零件插入变更后那一颗，用量按文件。**序号继承旧总成投产序号**。新总成生效=生效年月；失效抄项目结束月。节点 `bom_version` 写 **本张材料清单表头版本**（必填，禁止抄 snapshot SOP 字）；且必须与冲压工艺确认表表头版本 **同一字**；snapshot 头仍 SOP 字 |
| 未改总成 | **跳过** |
| 文件没有、库里仍有效 | **不动**。唯一例外是完成停止点名的那一棵 |
| 新交货总成已在库里 | **整单拒绝** |

禁止：把这份 Excel 当成新 `bom_version` 快照整表覆盖；在旧总成节点上改零件号；走 `BomNodeService.create_node`（走 `BomNodeWrite`）。内部号 / 总成图见第 3 节：总成、分总成不得空号；总成必须有图；变化行内部号以文件为准，没改的层从旧树抄。简图：本张清单有图用新图；零件号没变才抄旧树。**换号后的零件不准抄旧号图**（目录仍挂本张材料清单表头版本）。

SOP 再导：只更新 **生效月 = 项目 SOP 开始月** 且仍有效的树。已失效的、以及生效月是工程变更切点的 **整棵跳过**。

校验（失败则整份拒收）：

- 变更单第一道：项目与上传页一致；一次上传只能有一个变更年月，且须等于上传页。  
- 变更单第二道：变更前必须已有，变更后不得已有。变更前总成须仍有效；变更后总成系统里不能已有。一级/二级改图、此件不装：变更前零件必须装在这个总成上。改图/增加零件：变更后零件不得已在变更前总成上，也不得已是交货总成。  
- 变更类型四句、十列符合第 1 节。五种场景：变更后总成必填、必为新号、不得等于变更前总成。同一个总成只写一次；改了好几处（同属五种、同一对新旧总成）须挨着写并把变更前/后总成格子上下合并。完成停止不用填变更后总成。  
- 五种场景：材料清单该总成列 **必须等于** 变更单变更后总成（整号相同，不推算）。整本：材料清单全部 L0 = 五种场景变更单行的变更后总成集合。  
- 改图且零件层级=一级/二级：变更单变更后零件必须出现在材料清单对应层级。材料清单还须写出这条链上每个中间分总成的新号（样表 `122AB-1`）。种树只盖文件上的号，没写的层不换。  
- 该基地+项目只有一份投产清单头；上传页项目 = 变更单项目 = 材料清单第 3 行项目代号 = 确认表拆出的项目号。材料清单顾客名称、序号不互校。工艺确认表序号不互校。  
- 材料清单第 2 行版本与确认表表头版本必须同一字，均必填（含完成停止）。禁止抄投产 `D/00`、禁止空串。  
- 生效年月晚于旧总成生效月，且必须落在该项目有效期内（prep 再跑 `require_introducible`）。  
- 该投产 snapshot **已经有** SOP 生成过的采购对象清单头；没有则整单拒收（含完成停止）。insert 无头仍硬停，不代建空头。  
- 确认表每一个零件号、变更单已填的变更后零件，都必须出现在本本材料清单；缺号一次报完。  
- 交货总成、分总成内部号不得空；交货总成必须有总成图。变化行内部号以文件为准。同一份清单里一物一码。材料清单项目空不得跳过互校。  
- 此件不装：变更单钉的零件必须出现在材料清单且用量 0 + 备注含「此件不装」；中间层不装时下级必须同样标记。变更单一行不够。  
- 增加零件：是否改图只看变更单类型，不要用末两位字母去猜。新件备注禁止「此件不装」。

### 4.2 冲压库：按零件号对齐

格式就是冲压工艺切片确认表，同一 Parser。有效期写在零件行。此件不装、完成停止不填零件行 → **不加新行、旧号不到期**。设变 **不得**调用 SOP `save_parts` 拒新号路径。

| 文件里的零件号 | 系统做 |
|----------------|--------|
| 新号 | **旧号、新号都只认工程变更单，禁止按茎猜前驱、禁止把 AA 加成 AB。** 工艺/布点换号表 **不含** 层级=总成的改图（交货总成不是冲压工艺行）。一级/二级改图：旧号=变更前零件、新号=变更后零件。工艺表该行零件号必须等于这个新号。**先**让该旧号在同厂同项目仍有效的工艺行 **到期**到生效年月的前一月（行不删，有则继承 `seq_no`）；**再启用新行**。版本=本张工艺确认表表头，**且必须与材料清单表头版本同一字**（空表体、完成停止也不例外）。**改图换号：零件信息除零件号、版本、生失效外整行抄变更前那个旧号，工序整表相同**（确认表只用来出门禁/简图，不重写材料、尺寸、工序）。确认表零件简图落到 `{基地}/{项目}/{表头版本}/{新零件号}.png`：工程变更从原 xlsx 的「冲压工艺确认表」抽图（抽出来的单表会丢掉 WMF）。表里有图则写入新号工艺 `sketch_url`。**换号后的零件不准抄旧号图**；表里没图则新号工艺为空。增加零件：新号=变更后零件，无变更前零件可对 → 按确认表新插，`seq_no = max+1`，**不停任何旧工艺** |
| 已有号 | **一律跳过** |
| 表体空 | **不插、不到期** |
| 文件没有的旧号 | **不删、不到期**。只有变更单改图钉明的旧号才到期 |

`cost_ratio`：改图换号整表抄旧工序，比例一起带走。增加零件 / 无旧号可对 → 确认表解析默认。Excel 没有这一列。

到期只动变更单钉明的旧号，只在变更单 **一级/二级改图** 时做（写失效月，不删行）。禁止按字母版本同茎去搜「该停哪个」。旧号当月仍有工艺、且还挂在另一棵仍有效、本文件又不替换的树上 → **整份拒收**（`EC_PROCESS_SHARED_OLD`）。无工艺 as-of 的旧号不走这把锁。增加零件 **禁止**停任何旧工艺。

工艺表允许出现的新冲压号，认 **本文件材料清单相对旧总成换号或新加的号**（层级=总成的改图不进换号表，变更后零件为空）：

| 变更单 | 工艺表 |
|------|--------|
| 改图 | 一级/二级：材料清单里每个换了号、且旧号在该厂有仍有效工艺的冲压件，都必须有新号。新号必须等于变更单变更后零件。分总成不出工艺。层级=总成：不进换号表。禁止系统自己生成 AB/AC |
| 增加零件 | 新件按材料清单判断是冲压件时 **必须**含变更后零件；标准件 / 胶可省略。**禁止**停任何旧工艺 |
| 完成停止 / 此件不装 | 表体空 → **不加新行、旧号不到期** |

工艺表出现材料清单里没有的新号 → 拒收。材料清单换了号、旧号有仍有效工艺、工艺表却没有新号 → 拒收。旧号本来就没有工艺行 → 不必出。

### 4.3 模具布点：逻辑建立，不读 Excel

工程变更 **不要**「零件汇总」。导入 **不抽、不解析** 这张表；模板不带；Excel 里误带了也不读、不拒收。设变 **不得**调用 SOP `die/upload_service`，**不得** `parse_die_layout_excel`。模具信息按变更单 **逻辑建立**：一级/二级改图且变更前零件在该厂该项目有仍有效布点 → 从库里整行抄出新号布点；否则不建。层级=总成的改图不进换号表。新开模仍走投产布点页。

现场：冲压件改图通常还用原来那副模，只做改模。所以新号布点主表/工序必须 **完全抄旧号**，尤其 `alloc_ratio`（分摊比例）。确认表不重写模具尺寸、编号、分摊。

**简图：** 布点表不存 `sketch_url`。列表按零件号看工艺确认表落到新号工艺行的那张图。不要让新号工艺继续挂旧号图。

| 变更单 | 系统做 |
|------|--------|
| **改图** | 只一级/二级改图：旧号=变更前零件，新号=变更后零件。层级=总成不进这张表。禁止按茎猜旧布点。该旧号在该厂该项目有仍有效布点：旧布点 **到期**到生效年月的前一月（行不删）；**再启用新号布点**。主表除零件号、版本、生失效外整行抄旧（模具编号、材质、料厚、净重、板料、模具类型/方式/生产、长宽高、掏空、预估重量等）；工序整表相同，**`alloc_ratio` 必须一起带走**。版本=本张工艺确认表表头（与材料清单同一字，禁止 `None`）。已有新号跳过。无旧布点可对 → **不插** |
| **增加零件** | **禁止**停任何旧布点。新件无变更前零件、无旧布点可对 → **不插**（新开模走投产布点页，不在工程变更填） |
| **完成停止 / 此件不装** | **不插、不到期** |
| 文件没有的旧号 | **不删、不到期**。只有一级/二级改图换号且旧号有布点时才让旧号到期 |
| 旧号还挂在另一棵仍有效树上 | 只在旧号 **当月仍有工艺 as-of** 时 `EC_PROCESS_SHARED_OLD` 整份拒收。布点跟工艺共用 `revise_old_to_new`，不另开「有没有布点」的共享锁 |

#### 4.3.1 检具费：改图有则抄

另表 `stamping_gauge_fees`，唯一键 `location` + `vehicle_model` + `part_number`。细则见 [stamping-gauge-fee-design.md](../stamping/stamping-gauge-fee-design.md)。

| 变更单 | 系统做 |
|------|--------|
| **改图**（一级/二级） | 旧号有 `effective` 档，且新号尚无该唯一键 → 为新号 **插一行**：检具费（万元）、分摊万台、状态照抄；零件号改新号。旧号行 **不动**（历史月核价仍认旧号） |
| 无旧档 / 新号已有 | **不插**、不覆盖。不是硬门禁 |
| 完成停止 / 此件不装 / 增加零件 | **不抄** |

`effect_link`：`EFFECT_GAUGE_FEE`；`before_id` = 旧行 id，`after_id` = 新行 id。  
**回滚必须删除 `after_id` 新行**；旧行不动。只删本趟链接登记过的行，禁止按零件号扫库。

#### 4.3.2 模具费结果：改图有则抄

抄的是已落库年度结果 `stamping_die_fees`（含各序 `stamping_die_fee_items`），**不是**再跑一次模具费计算、不写 calc_log。细则见 [stamping-die-fee-design.md](../stamping/stamping-die-fee-design.md)。

| 变更单 | 系统做 |
|------|--------|
| **改图**（一级/二级） | 旧号在 **`year >= 变更生效年`** 的结果行，且新号同年键不存在 → **整单抄**主表+各序。`source_die_part_id` 绑本趟新建布点；`source_die_process_id` 置空（软指针）。金额/调整/最终费照抄；审核重置 `pending`，审核人时点清空。版本/供应商优先用新布点快照。旧行 **不动** |
| 无旧结果 / 新号同年已有 | **不插**、不覆盖。不是硬门禁 |
| 完成停止 / 此件不装 / 增加零件 | **不抄** |

`effect_link`：`EFFECT_DIE_FEE`；`before_id` = 旧主表 id，`after_id` = 新主表 id（明细随主表级联）。  
**回滚必须删除 `after_id` 新主表（级联明细）**；旧行不动。链接 `sort_no` 排在布点之后，逆序回滚时 **先删模具费/检具费再滚布点**（避免 `source_die_part_id` `RESTRICT` 挡删布点）。

与核价引擎互补：引擎 `annual_die_fee` 按「该年+基地+项目已有**任意**模具费行则整项跳过」判定（不做布点↔费用逐件对齐）。旧号已有结果时靠本条抄到新号；旧号无结果时仍靠引擎补算。见 [costing-engine-design.md](../costing/costing-engine-design.md) §5.2。

### 4.4 采购对象：设变导入后自动带出

**导入后不必再点「开始生成」。** 种树成功后，同一事务按现网分类规则扫新树插行。对象行 **不加** 生失效四列；展示与过期筛 **只认所属 L0 树根**（列表默认包含已过期，不按变更月裁）。细则见 [bom-procurement-objects-design.md](../bom/bom-procurement-objects-design.md) §0.1 / §14。清单**列表取件**：**基地 + 项目**，**必须爬到树根**；版本可选=L0 版本字浏览；**不要**用材料清单表头 `EC-*` 去找清单头（头上仍是 snapshot SOP 字）。「版本」三义见[采购对象清单](../bom/bom-procurement-objects-design.md)文首词典（与协议同形）。

该 snapshot 一旦有工程变更写入的树，采购对象 / 拆解「开始生成」拒绝（门禁之 2）。缺对象只能工程变更重传。**生成页只读 snapshot（SOP）**；设变增量不走生成页。

prep **整单**（含只做完成停止）必须已经有 SOP 生成过的采购对象清单头。没有 → 整单拒收。`insert_for_new_tree` 无头仍硬停，**不代建空头**，不把新建头挂进 `EFFECT_PROCUREMENT_LIST`。设变后的总成根对不上或 `after_root_id` 空 → 硬停，禁止 warning 跳过。

匹配只认被替换的那一棵旧树。确认三态 / 确认人时 / 确认备注 / `supplier_name` **按现网**：先同 `part_number` + `section` + `object_kind`；对不上再按新旧树同一位置（同级兄弟 `sort_no`）抄旧行。不按字母版本同茎配对，也不另走变更单号对。

| 新树上的节点 | 系统做 |
|--------------|--------|
| 列入采购对象，旧树对上（同号或同一 `sort_no` 位置），且 `object_kind` 不变 | 插新行；确认三态 / 确认人时 / 确认备注 / `supplier_name` **从旧树抄**。不抄 `audit_status` |
| 列入采购对象，对不上 | 插新行，待确认、厂家空 |
| 核对区 | 插新行；无确认可抄。用量 0 +「此件不装」未插入的叶子不插 |
| 完成停止 | 不插 |
| 旧树已有行 | 不动 |

`object_kind` 变了当新号，不抄确认。抄来的厂家不跑 `require_enabled`。

#### 4.4.1 焊接拆解：从旧树结果抄到新树

**不得**调用现网整包 `POST /generate`。**禁止**按新节点 `weld_info` 重新自动拆（用户可能已改过过程量）。

做法：只认种树给出的 `旧 bom_nodes.id → 新 bom_nodes.id` 对照。读对照键上旧树已有拆解结果，为每个对新节点 **再插一套**：主表身份对齐新节点；过程量等结果字段与 **全部明细行**（可多行）从旧结果照抄；rollup 按新树重算。旧拆解行不动。此件不装未进对照的节点不抄。增加零件等无旧拆解可对的新节点 **不插、不重拆**。新行审核态待审。`bom_version` **抄新树根字**，不抄 snapshot 头。完成停止不插。门禁之 2、之 3 见 §4.6。细则见 [welding-process-breakdown-design.md](../bom/welding-process-breakdown-design.md)。

### 4.5 价表与核算

种新树时 **抄** 包装运输费与年度零件价（有则抄、无则跳过、新号同年已有不覆盖，非硬门禁，不读 Excel）。完成停止不抄。没换号的不必出新价行。不装的零件不进该月核价。增加零件的 **新号** 无旧年度价可对，该号仍人补。

**改图必须抄** 检具费档案与（若有）模具费结果，见 §4.3.1 / §4.3.2。零件价按月取号：检具按新号档案（万元÷万台→元/件），模具费按年+新号取 `final_die_fee`；缺档计 0（与现网 resolver 一致）。

#### 4.5.1 包装运输费：种新树有则抄

抄的是已落库 `bom_packaging_transport_fees` 整行（含 `unit_packaging_fee` / `unit_transport_fee` / `other_fee` / 合计等），**不是**再导 Excel。唯一键 `location` + `year` + `vehicle_model` + `part_number`。总成核价按 **交货总成零件号** 取包装。

| 变更单 | 系统做 |
|------|--------|
| **改图 / 此件不装 / 增加零件**（种了新交货总成） | 旧交货总成 `year >= 变更生效年` 的行，且新总成同年键不存在 → **整行抄**到新交货总成号。金额/器具字段照抄；审核重置 `pending`；Excel 溯源列不抄。旧行 **不动** |
| 无旧行 / 新号同年已有 | **不插**、不覆盖。不是硬门禁 |
| 完成停止 | **不抄** |

`effect_link`：`EFFECT_PACKAGING_FEE`；`before_id` = 旧行 id，`after_id` = 新行 id（一年一行一条）。  
**回滚必须删除 `after_id` 新行**；旧行不动。只删本趟链接登记过的 id，禁止按零件号扫库。

#### 4.5.2 年度零件价：换号有则抄

抄的是已落库 `bom_annual_part_prices` 整行（含已算好的 `unit_price`，**禁止**再按转换系数重算）。唯一键 `location` + `year` + `part_number`（无车型）。对号只认种树 `旧 bom_nodes.id → 新 bom_nodes.id` 里 **零件号变了** 的对（交货总成、中间分总成、改图层）。禁止只走冲压一级/二级换号表。

| 变更单 | 系统做 |
|------|--------|
| **改图 / 此件不装 / 增加零件**（种了新树） | remap 中旧零件号 ≠ 新零件号，且旧号 `year >= 变更生效年` 的行，新号同年键不存在 → **整行抄**。审核重置 `pending`；Excel 溯源列不抄。旧行 **不动** |
| 没换号 / 增加零件无旧号 / 无旧行 / 新号同年已有 | **不插**、不覆盖。不是硬门禁 |
| 完成停止 | **不抄** |

`effect_link`：`EFFECT_ANNUAL_PART_PRICE`；`before_id` = 旧行 id，`after_id` = 新行 id（一年一行一条）。  
**回滚必须删除 `after_id` 新行**；旧行不动。只删本趟链接登记过的 id，禁止按零件号扫库。

引擎：该月只收有效树根（按 SOP `seq_no` 序）；叶子冲压价抄该月有效工艺行。总成卡抄树根项目号、**节点**版本字；发现范围仍按 snapshot 头版本。完成停止不停工艺行：零件价月账仍可能算到旧总成下的冲压号；总成核价不收已失效的树。

### 4.6 与投产切片怎么协作

BOM / 工艺 / 布点的 Parser、UNIQUE、引擎发现键、`create_node`、投产空表硬停：**都不改**。工程变更抽表后自己写入，不走投产三条覆盖链。

| 现网 Parser / UNIQUE | 本切片 |
|----------|------------|
| BOM Parser 只读第一张表 | 按表名抽出 `车身件材料清单` 再交给 Parser |
| 工艺 Parser 自动找「零件号+工序」或退回第一张 | 按表名抽出 `冲压工艺确认表` |
| 布点 `find_sheet` 扫到「零件号」就用 | **禁止**抽「零件汇总」，**禁止**对整本调用 `parse_die_layout_excel`。布点 **逻辑建立**：改图从库里旧号抄，不读 Excel |
| `bom/bom/upload` 用 Excel 头版本对 snapshot | 本切片不走这条。按基地+项目找 **唯一** 投产清单头，头仍 D/00 |
| `create_node` 强制节点版本=头 | 走 `BomNodeWrite` |
| 布点 SOP 空表体硬停 | 工程变更不走 `die/upload_service` |
| 工艺 SOP 拒新号 | 本切片自己按号增行；已有号跳过 |
| 引擎 `L0Scope` 分组仍用 snapshot 头（拆解 **生成** 找包） | 拆解与焊接费 **行** `bom_version` 抄树根；计算和列表认树根，不认 SOP 头 |
| 宪法同步 Excel 封闭名单 | 工程变更是长任务（`task_id`），不进该名单 |

| 门禁 | 改哪个入口 | 判定 |
|------|------------|------|
| 1 | `bom/bom/upload/persist/nodes.py` 再导对齐树 | 只更新：树根仍有效 **且** 生效月 = 项目 SOP 开始月。已失效、或生效月是工程变更切点的整棵 **跳过** |
| 2 | 采购对象 / 焊接拆解「开始生成」 | 该 snapshot 存在已失效树根，**或** 存在生效月 ≠ 项目 SOP 开始月的树根 → 409 |
| 3 | 引擎 `annual_welding_breakdown` | 年交集已齐 → 跳过；缺拆解 → **仍调** 现网 `generate`；若 `snapshot_blocks_full_generate` 拦住 → `EC_GATE_ENGINE_BREAKDOWN`（禁止 runner 一律硬停） |

写入顺序（一次事务，失败全滚）：

```text
变更单 + 材料清单 + 工艺硬门禁校验（不读零件汇总）
  → 按表名抽业务表（缺工程变更单 / 材料清单 / 工艺确认表整单失败）
  → 按变更单行顺序、一次事务：
     完成停止：旧交货总成到期（不删行）
     改图 / 增加零件 / 此件不装：旧交货总成到期 + 启用新树
  → 每棵新树：本树采购对象插行、本树焊接拆解从旧树结果抄插（主表+全部明细；禁止按焊信重拆）
  → 工艺表按号增行一次（仅改图行才让旧号到期；不删行）
  → 布点：不读 Excel；改图换号若旧号有布点则逻辑建立新号（整行抄旧，含 alloc_ratio），旧布点到期；简图只看新号工艺行
  → 检具费：改图旧号有生效档则抄到新号（EFFECT_GAUGE_FEE）
  → 模具费：改图旧号有 year≥生效年结果则抄到新号（绑新布点；EFFECT_DIE_FEE）
  → 包装运输费：种新树则旧交货总成 year≥生效年抄到新总成（EFFECT_PACKAGING_FEE）
  → 年度零件价：种树 remap 换号则 year≥生效年抄到新号（EFFECT_ANNUAL_PART_PRICE）
  → 写变更单行 + 效果链接 → 回写上传头 success
```

三库都禁止整包删。再传一本（变更单再写出另一对新旧号，样表从 AB 写成 AC 也照抄）同一套，系统不推下一位字母。

## 8. 产品：上传与列表

单独做，不塞进投产三页。此件不装、增加零件都在同一本 Excel 里，不另开按钮。

### 8.1 上传

| 字段 | 与 Excel 怎么校 |
|------|----------------|
| 基地 | 找到该基地+项目的唯一投产清单。变更单无此列 |
| 项目 | 必须 = 变更单「项目」= 材料清单「项目代号」= 该投产清单项目 |
| 年度 + 月份 | 必须 = 变更单「生效年月」 |
| 文件 | `.xlsx`；工程变更单 + 材料清单 + 工艺确认。**不要**「零件汇总」（模具逻辑建立，简图从工艺确认表抄） |

顾客只来自 **投产清单头**（以前那份清单抄过来的 `customer_name`），工程变更材料清单「顾客名称」是人抄的格子，**不读、不互校、不落库**。版本从材料清单、工艺确认表头读，不要合成一个「上传版本」字段。

同基地+项目允许排队多个任务；本本任一变更后总成已被成功写入或进行中的任务占用 → 409。失败任务不占号。文件一入队即 `file_trace.register_existing`（失败校验也留档）。上传走后台任务。

`GET /api/engineering-change/template` 即样表这一本，文件名 `工程变更导入模板.xlsx`。模板 **不带**「零件汇总」。上传文件里误带了也不读。模板下载不写 `upload_files`。

### 8.2 列表与详情

分页。**列表以变更单行为粒度**（一本 Excel 成功后 N 行，同一 `upload_log_id`）。列对齐样表工程变更单十列：项目、生效年月、变更前/后总成、总成名称、变更类型、零件层级、变更前/后零件、零件名称；另加材料清单序号、基地、上传人、源文件、整本状态。

点行看详情：失败 `message` 与当时 Excel 下载。操作：**删除 = 回滚**。删列表任意一条变更单行，都按 `upload_log_id` 把本次上传全部回滚，并 **物理删除** 上传头 / 变更单行 / 效果链接，列表不再留「已回滚」。存档 Excel **保留**。

### 8.3 三张表

全新切片：现网历史表直接 DROP，不迁数据。

一次尝试一行上传头 `engineering_change_upload_logs`（`pending` / `success` / `failed`）。成功后按变更单行插入 `engineering_change_orders`（1 上传头 : N 变更单行；十列 + `excel_row` + 变更单实体 `id` + `before_assembly_node_id` → `bom_nodes` RESTRICT）。缺 `before_assembly_node_id` 的存量表启动时 DROP 三表重建（清孤儿，不迁数据、不调回滚 Service）。`engineering_change_effect_links` 存 `upload_log_id`、`change_order_id` 与前后实体 id：`assembly_l0` / `process_part` / `die_part` / `gauge_fee` / `die_fee` / `packaging_fee` / `annual_part_price` / `procurement_object` / `welding_breakdown` / `procurement_list`。缺链接 = 不可回滚，禁止标成功。回滚按 `sort_no` **逆序**：先删本次新插的年度价/包装/模具费/检具费，再滚布点/工艺/树（见 §4.3.1 / §4.3.2 / §4.5.1 / §4.5.2）。

删除本次变更：上传头 `success`（失败记录可直接物理删除，进行中禁止删）；本本全部变更单 `active`；其后没有以本本任一 `after_assembly` 为变更前总成的未删除记录。按效果链接逆序恢复业务对象，同一事务里 **物理删除** 本本三张表。存档 Excel **保留**。已审采购对象须先反审。不留 `rolled_back` 行。

### 8.4 API

前缀 `/api/engineering-change`。JSON 一律 `ApiResponse[T]`；分页 `page` + `size`。异步上传 HTTP **200** + `AsyncTaskAcceptedVO`。

| 方法 | 路径 | 权限 | 出参 |
|------|------|------|------|
| GET | `/template` | `ENGINEERING_CHANGE_UPLOAD_UPLOAD` | 样表文件流 |
| POST | `/upload` | 同上 | `AsyncTaskAcceptedVO`（multipart：基地/项目/年/月/file） |
| GET | `/upload/tasks/{task_id}` | view / upload / order-list view 任一 | `AsyncTaskProgressVO` |
| GET | `/change-orders` | `ENGINEERING_CHANGE_ORDER_LIST_VIEW` | `PageResult[EngineeringChangeListRowVO]`（变更单行；`upload_log_id` 整本删除） |
| GET | `/change-orders/{upload_log_id}/original-file` | 同上 | 当时 Excel 文件流 |
| DELETE | `/change-orders/{upload_log_id}` | `ENGINEERING_CHANGE_ORDER_LIST_DELETE` | 整本回滚后物理删除本记录 |

步长建议：10 校验变更单与抽表 → 40 种树/失效 → 70 对象+拆解 → 90 工艺；布点逻辑建立（简图从工艺确认表抄）→ 100 回写日志。失败：业务事务全滚，不留半套新树。

## 9. 拒收原因

用 `BusinessException(message=..., code=400|409)`；常量名放 `app/common/engineering_change_gates.py`。对人只展示 `message`：常量后补两边的字 / 零件号 / 改哪一格。

| 常量名 | HTTP | 要旨 |
|--------|------|------|
