## 写作要求（再次强调）

1. 数字只能来自上述 JSON；禁止编造。
2. 金额单位是 **元**，禁止写成万元，禁止 ÷10000。
3. 必须包含「异常与风险」专节（无异常也要写明未见）。
4. 标题使用 JSON 中的具体基地、年、月（及项目/物料清单版本若有），不要写「本月」。
5. 不要输出 UTC 技术时间戳解释；面向采购业务人员表述。
6. **全文使用中文**：报告正文不得出现英文字段名、代码术语（如 grand_total、partial_count、ok、tight、summary、Pack 等）；必须遵守 `_shared/chinese_style_rules.md`。
7. **通俗易懂**：像采购主管向同事做口头汇报，禁止机器翻译腔和「事实/影响/动作」三段式公文套话；用自然段落说清楚即可。
8. 报告开头的类型与受众须翻译为中文（如「概览分析」「采购主管」），禁止照抄上方的英文 `report_type` / `audience` 值。
9. **禁止 dashboard / 仪表盘内容**：LLM 报告与系统仪表盘无关。用户问单件核价/价格详情时，只写该件明细；不要写基地总盘、头部排行、成本结构占比等仪表盘板块。正文禁止出现英文 dashboard 或「仪表盘」字样（除非用户原话如此）。
10. **成品 vs 冲压域**：`part_existence` 中 `primary_source=l0` 或 `applicable=false` 的冲压库表示该件是成品供货总成、不在冲压库检索，**不得**写成风险或「未找到需警惕」。
